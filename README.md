# 交易分析决策系统

一个本地运行的交易行情与技术分析 Web 应用。系统以 SQLite 缓存 2020 年以来的日线和
美股分钟行情，提供行情总览、K 线与指标、直线趋势线分析、数据增量更新、数据库浏览和
可选择的双数据库备份。

项目优先保证 Windows 原生环境可运行，同时尽量兼容 Linux / WSL。若平台行为存在差异，
以 Windows 为优先支持环境。

## 1. 系统概览

| 模块 | 当前能力 |
| --- | --- |
| 行情总览 | 展示自选标的、涨跌幅和更新时间；支持三列收藏指标、排序、拖拽和移除 |
| 数据源 | 美股/ETF 优先 Alpaca；不支持时使用 Yahoo Finance、Twelve Data |
| 历史范围 | 首次完整导入从 `2020-01-01` 开始 |
| K 线 | `1m`、`15m`、`1h`、`4h`、`1D`、`3D`、`1W`、`1M` 及自定义周期 |
| 指标 | MA、EMA、Wilder ATR、相对 ATR、R²、WTME、RSI、MACD 等；按“标的 + K线周期”保存配置 |
| 智能分析 | 在日线周期识别上涨支撑线、下跌压力线和趋势结构事件 |
| 历史回测 | 可视化/代码策略、三种选标模式、严格事件时钟、后台运行、实时资金曲线与审计日志 |
| 实时决策 | 行情总览全标的策略指标面板、定时正式决策、邮件通知与完整审计 |
| 本地存储 | 主数据库保存业务数据；分钟数据库压缩保存 1 分钟原始行情 |
| 运维 | 数据库浏览、主库/分钟库可选备份、显式退出和浏览器关闭兜底 |

核心数据流：

```text
Alpaca / Yahoo Finance / Twelve Data
                  │
                  ▼
       行情路由、限流与增量导入
            │             │
            ▼             ▼
  market_data.sqlite  intraday_data.sqlite
            │             │
            └──────┬──────┘
                   ▼
       Flask API → Canvas K线与分析界面
```

## 2. 快速开始

### 2.1 环境要求

- Python 3.10 或更高版本
- Windows、Linux 或 WSL
- Alpaca 账号：分钟历史和 Alpaca 美股/ETF 日线
- Twelve Data Key：作为部分标的的日线备用源
- Yahoo Finance 不需要 API Key

### 2.2 Windows 安装

PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

如果 PowerShell 禁止执行激活脚本，可使用 CMD：

```cmd
py -3 -m venv .venv
.venv\Scripts\activate.bat
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 2.3 Linux / WSL 安装

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 2.4 配置 `.env`

在项目根目录创建 `.env`：

```env
TWELVEDATA_API_KEY=your_api_key_here
ALPACA_API_KEY=your_alpaca_key_here
ALPACA_SECRET=your_alpaca_secret_here

FLASK_HOST=127.0.0.1
FLASK_PORT=5000
AUTO_OPEN_BROWSER=true
AUTO_SHUTDOWN_ON_BROWSER_CLOSE=true
ANALYSIS_MAX_WORKERS=4
BROWSER_OPEN_COMMAND=
```

可选配置说明：

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `FLASK_HOST` | `127.0.0.1` | 本地监听地址 |
| `FLASK_PORT` | `5000` | Web 服务端口 |
| `AUTO_OPEN_BROWSER` | `true` | 启动后自动打开浏览器 |
| `AUTO_SHUTDOWN_ON_BROWSER_CLOSE` | `true` | 浏览器无心跳后自动退出 |
| `ANALYSIS_MAX_WORKERS` | `4` | 趋势线冷计算进程上限，范围 1～4 |
| `REALTIME_MAX_WORKERS` | `4` | 同时执行关键时点决策的线程上限，范围 1～8；普通等待任务不占用这些线程 |
| `REALTIME_EVENT_GRACE_SECONDS` | `60` | 事件超过该延迟后不使用过时行情补算 |
| `REALTIME_RECOVERY_STALE_SECONDS` | `300` | 进程重启时判定旧任务心跳失效的时间 |
| `BROWSER_OPEN_COMMAND` | 空 | 自定义浏览器启动命令 |
| `ALPACA_TRADING_BASE_URL` | Paper API | Alpaca 标的能力检测地址 |

不要提交包含真实 Key 和 Secret 的 `.env`。

### 2.5 启动

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
python app.py
```

Windows CMD：

```cmd
.venv\Scripts\activate.bat
python app.py
```

Linux / WSL：

```bash
source .venv/bin/activate
python app.py
```

默认访问地址：

```text
http://127.0.0.1:5000
```

调试时禁用自动打开浏览器：

```powershell
$env:AUTO_OPEN_BROWSER="false"
python app.py
```

```bash
AUTO_OPEN_BROWSER=false python app.py
```

## 3. 页面与使用方式

### 3.1 查看行情

查看行情页默认显示行情总览：

- 点击任意行进入标的详情。
- 点击列标题进行排序；在标的代码升序模式下可拖拽调整顺序。
- “指标列 1–3”可各选择一个收藏指标并展示其最新日线值；三列都支持升降序，选择保存在
  当前浏览器中。相同指标只显示一次，取消收藏后对应总览列会自动清空。
- 行情总览的标准指标统一按前复权日线计算，只读取已经落库的公司行动，不会因打开总览
  触发外部公司行动请求。若最新日线尚未收线，不额外显示“盘中”标签；悬停仍可查看价格
  口径、数据日、截至时间以及该数值尚未收线的说明。
- 标的详情的“显示美股休市日 K 线”按标的保存。开启时，K 线及 MA、ATR、WTME 等指标
  纳入周末和美股节假日；关闭时，服务端使用保存的 XNYS 日历先删除所有非交易日，再进行
  指标和 `3D`/`1W`/`1M` 聚合。它不再只是按星期六、星期日判断。
- 详情页的加号/勾选图标用于加入或移出总览。
- 移出总览只改变显示与自动更新范围，不删除历史行情、分钟数据或指标配置。
- 总览中的“自动更新”开关是服务端唯一的行情总览更新协调器：应用打开时更新一次，开启后
  每 5 分钟更新一次；实时决策详情中的同名开关与这里共享同一状态。关闭开关不取消启动时
  的一次更新，也不影响正式实时决策按候选池独立校验和取数。

### 3.2 查询和更新单个标的

查询框旁的“包含分钟数据”决定本次查询或手动更新是否处理分钟历史：

- 数据库没有该标的日线时，首次查询自动获取 2020 年以来的日线。
- 未勾选时，只读取或更新日线；进入详情的默认 `1D` 首屏直接读取主数据库，不打开分钟库、
  不读取分钟同步状态，也不等待分钟任务轮询。
- 勾选且 Alpaca 支持时：
  - 没有完整分钟历史：从 2020 年开始初始化；
  - 已有完整分钟历史：从最近数据附近增量更新。
- Alpaca 不支持的标的只能使用日线，界面会给出提示。
- 详情页只保留一个更新图标，更新内容完全由复选框决定。
- 点击更新时先刷新近期窗口，再按最近 260 个已完成美股交易日校验日线日期与 `is_complete`
  状态；如有缺口，只从最早缺口开始补数，完成后再次校验并在状态栏显示完整日线截止日。
  已核验的晚成立标的按实际上市起点缩短校验范围；无法确认或补齐时明确显示警告，不把
  “API 请求成功”当作“数据完整”。
- 明确勾选分钟数据的查询和手动更新在后台执行，详情页显示进度条；分钟数据按分页进度
  每约 3 秒刷新一次，提示“已更新至 YYYY年MM月DD日”及累计页数、行数，完成后再刷新图表。
- 同一标的已有查询或更新任务时，重复查询会复用该任务，不会启动第二次下载；如果重复
  请求勾选了分钟数据，现有日线任务会自动升级并继续完成分钟导入。不同标的是相互独立
  的任务，返回总览或切换标的不取消后台下载，界面只展示当前最后一次查询的进度和结果。
- 已核验的晚成立标的按供应商实际历史起点判断完整性。例如 BTC/USD 的 Alpaca 分钟历史
  从 2021-01-01 开始，完整导入后不会因为缺少 2020 年数据而被误判并重复全量下载。

每次进入标的详情默认回到 `1D` 周期。
只有切换到 `1m`、`15m`、`1h`、`4h` 或自定义分钟周期时，页面才读取分钟 K 线及其同步状态。

### 3.3 K 线交互

- 拖拽图表平移，滚轮缩放。
- 默认展示最近 150 根 K 线。
- 分钟周期前端请求最新 300 根，再展示最近 150 根，避免 `1h`、`4h` 扫描过多历史。
- 左轴显示价格，右轴显示相对当前视图首根开盘价的涨跌幅。
- 光标命中蜡烛实体或影线时显示 OHLCV 浮层。
- 支持夜间/日间主题。
- 美股/ETF 可选择“全复权”“仅拆股复权”或“原始价格”；页面列出当前范围内的拆股、
  分红和更名等公司行动。只有明确标记为 Alpaca 原始价格的数据才执行复权，未知口径会
  保持原样并提示，避免重复复权。
- 详情 K 线默认使用全复权。MA、EMA、ATR、相对 ATR、R²、WTME、RSI、MACD 等指标始终由服务端基于
  当前所选 K 线及同一复权口径计算，浏览器只负责按 K 线键对齐和绘制；图例显示价格口径，
  最新 K 线未结束时显示“盘中”。
- 光标进入副图时，十字线贯穿主图与副图，并显示对应日期的 ATR、R²、WTME、RSI 或 MACD
  DIF/DEA/柱状值；MACD 柱状值使用 `DIF - DEA`，不乘 2。
- 行情读取期间同一状态条显示同步进度；完成后该位置切换为公司行动摘要，不同时占用
  两行空间。

预设周期：

| 分时 | 日线及以上 |
| --- | --- |
| `1m`、`15m`、`1h`、`4h` | `1D`、`3D`、`1W`、`1M` |

自定义周期：

- 分钟：1～390 分钟；
- 日线：1～365 日；
- 自定义视图首次使用时写入 `symbol_chart_views`。

### 3.4 数据库浏览

数据库浏览页当前分页读取主数据库中的业务表，支持：

- 每页最多 50 行；
- 跨当前表全部字段的文本搜索；
- 页码跳转；
- 选择备份主数据库、分钟数据库或两者。

分钟数据库为大体量压缩库，目前不通过表格浏览器直接逐行展示，以免浏览器误加载大量
分钟记录。

### 3.5 历史回测

- 策略列表首次使用时写入三种真实行情测试策略、内置的“急跌回避与ATR动量轮动策略”，
  以及“七星ETF轮动策略”的小池和大池预置。
- 前端只允许新建非代码策略；代码模式由项目代码注册并作为已保存策略直接展示。
- 删除会真实移除策略记录；已完成运行仍保留不可变策略快照和结果。
- 非代码策略支持 single、distribution、competition；竞争买入本身即为策略规则，额外的
  风险/退出规则可留空，并支持候选检查时点、最低入选评分和目标不变时不再平衡。公式支持
  OHLCV、MA、EMA、Wilder ATR、相对 ATR、R²、WTME、RSI、MACD、急跌过滤及布尔/比较运算。
  交易规则标题旁的问号通过点击打开完整语法说明弹窗。
- 内置“急跌回避与 ATR 动量轮动”代码策略的完整参数、计算公式、数据边界、当前配置差异
  和改进建议见 [策略专项说明](docs/rapid_drop_atr_rotation.md)。
- 设置起止日期、初始资金、1–10 倍账户杠杆、每股/最低手续费、滑点、碎股、无风险利率、
  比较基准及是否生成详细日志后运行。关闭日志不会影响成交、权益曲线和指标，也不会生成、
  实时传输或持久化审计日志，可进一步降低长回测的 CPU、内存和数据库开销。杠杆账户按
  分钟监控权益，爆仓后强平并提前结束，但仍生成完整财务结果。
- 每个策略保存独立的市场配置。当前只开放“美股（XNYS / America/New_York）”：日线指标
  只使用实际美股交易日，`HH:MM` 按美东时间解释，提前收市按保存的日历开收盘时间处理。
  该字段为以后增加加密市场或 A 股保留扩展边界。
- 新策略默认结束日期为当前日期前一天、每股手续费 0.01 美元、每笔最低手续费 1 美元、
  年化无风险利率 4.5%。
- “验证”会同时检查策略结构及回测所需日线/分钟线完整性。相对最新已完成美股交易日最近
  30 个自然日内的缺口会按标的自动补齐并复检；页面显示当前正在补齐的标的。直接点击
  “运行”只执行同一套只读预检，发现缺口时不补齐、也不创建失败运行记录。
- 工作区在运行中持续更新策略/基准曲线、保留的关键指标、成交摘要和分级日志；尚未产生的
  指标显示“运行中”。顶部只展示运行结果、总/年化收益、最大回撤、Sharpe、Sortino、交易
  次数和胜率；总收益及年化收益大于 0 为绿色、小于 0 为红色、等于 0 保持默认颜色。
- 回测由单 worker 专用后台线程串行执行；进度数据增量同步，实时指标按固定进度步长最多
  重算约 200 次，并在每日边界主动让出请求执行权，避免长回测明显阻塞历史结果和精细化
  分析页面。
- 回测数据层按标的建立日期、交易时段和公司行动累计因子索引。有限窗口指标只读取所需尾部
  数据；EMA、ATR、RSI、MACD 等递归指标在公司行动归一化坐标中按参数一次计算并复用；同一
  规则求值与审计日志共享指标缓存。正常固定资产池下总执行量随交易日数近似线性增长，不再
  为每个新交易日重复扫描从回测起点开始的全部历史。
- 收益曲线下方的“精细化分析”支持 1、3、6、12 个月区间，以及已完成交易日范围内的
  自定义起止日期。运行中的回测完成首三个自然月后即可打开，数据随 SSE 进度更新；终态短
  回测则自动按实际可用长度展示。
- 精细化分析按区间首个可用收盘点归零，对比策略、资产池各单一标的和资产池等权曲线；
  `auto` 即等权基准，显式基准若已在资产池中不重复绘制。图例可逐线隐藏，也可批量切换。
- 曲线日期联动紧凑决策面板：竞争策略按评分降序显示过滤、评分和代入值后的最终公式，
  公式值最多保留四位有效数字；非竞争策略显示逐条规则及结果。下方原始日 K 可切换资产池
  标的，以独立配色的 B/S 箭头徽标标记成交，并汇总买卖数、盈利卖单、已实现盈亏、手续费
  和扣除手续费/滑点后相对区间起始总权益的收益率。
- 新建运行会保存一行不可变的运行参数摘要，点击历史运行“查看”时展示；旧运行没有摘要
  时保持空白。
- 页面右上“回测结果”展示所有策略的历次运行总览，可按页查看回测区间、标的、杠杆、
  收益和最大回撤；点击某行进入只读历史详情，运行设置仍通过右上角按钮查看且不能修改。
  批量“删除”会让所选终态运行从普通界面消失，并清除详细日志及每日权益/持仓节点；
  数据库保留隐藏的策略快照、运行设置和总览指标，供将来实现摘要恢复。
- 启用日志时可下载纯文本 LOG；XLS 始终可下载，并包含运行摘要、逐笔买卖明细及已生成的
  代码策略自定义分析。关闭日志的运行不会提供 LOG，自定义日志工作表为空。
  急跌/ATR 策略的自定义表按日为每个候选成对展示评分公式与结果，并横向列出各硬过滤、
  最终操作和卖出 PnL；七星策略按日展示全池评分、各类过滤结果和最终操作。
- 资金曲线支持鼠标十字线，显示对应日期、权益、现金、收益率和各标的持仓比例。
- OPEN 读取前一日数据并按当日开盘成交；具体分钟读取事件前最近一根完整分钟，并按
  事件时刻起首个可成交分钟开盘成交，因此停牌或熔断期间的订单会等到恢复交易；
  CLOSE 信号延迟到下一交易日开盘，禁止同一收盘价成交。

完整策略语义、计算公式、公司行动和审计说明见
[历史回测模块文档](docs/backtest_module.md)。
七星策略的池、原算法复刻、参数、事件顺序和数据准备另见
[七星 ETF 轮动策略说明](docs/sevenstar_etf_rotation.md)。

## 4. 数据源与更新规则

### 4.1 数据源优先级

| 场景 | 数据源路由 |
| --- | --- |
| 首次获取日线 | Alpaca（支持时）→ Yahoo Finance → Twelve Data |
| 总览批量同步 | Alpaca；失败或不支持的标的继续尝试 Yahoo，再尝试 Twelve Data |
| 手动只更新日线 | Alpaca 支持时直接使用 Alpaca；不支持时按 Yahoo → Twelve Data |
| 正式实时决策 | 所需完整历史从策略市场序列读取并补缺；股票事件价使用 Alpaca IEX，BTC/USD 使用 Alpaca Crypto |
| 分钟历史 | 仅 Alpaca |

`symbol_aliases` 保存公共代码、显示名称和不同供应商代码之间的映射，例如指数、收益率和
贵金属可能在不同数据源中使用不同代码。

### 4.2 启动与总览自动更新

服务启动时立即启动一次后台同步，目标严格限定为当前显示在行情总览中的标的：

- 每个标的先按最近 260 个已完成美股交易日校验本地日线；完整时不重复请求历史日线，存在
  缺日或未完成日线时才从最早缺口开始补齐并复核；
- 美股常规交易时段另取一次批量 IEX snapshot，作为当天未收线日线写入；
- 自动同步不导入或增量更新分钟历史，分钟数据仍只在用户明确勾选“包含分钟数据”后处理；
- Alpaca 不支持的总览标的：按原有日线路由更新；
- 不在总览中的标的：不会自动更新日线或分钟数据。

服务端只有一个行情总览外部数据更新协调器。启动时固定执行一次；其开关状态保存在
`system_settings`，开启后每 5 分钟沿用同一范围和规则，开启动作本身也会立即触发一次。
同一分钟内重复点击只附着到正在运行的总览任务。单个标的失败不会中断其他标的，后续轮次
可再次尝试。行情页面
每 60 秒只重读一次内部数据库，让总览和已打开的 K 线及时看到服务端同步结果，不会因此
额外请求外部行情。关闭这个开关只停止行情总览的周期更新，不会阻止实时决策任务在正式
事件时点校验完整历史并独立调用 Alpaca 股票/加密 API 获取任务候选池的精确快照。

两个总览复用同一个更新图标：“查看行情”中手动刷新全部总览标的的日线数据；切换到
“智能分析”后才会手动重算全部标的的趋势线，两条任务链互不触发。

趋势线分析不再随服务启动或行情同步自动重算。在“智能分析”总览点击更新图标，才会
手动启动全部标的的趋势线更新。

### 4.3 增量窗口

- 单标的手动日线更新先回看最近 5 个自然日，再按完整性校验结果从最早缺口补齐；
- 总览自动/周期更新先做本地完整性校验；Alpaca 标的历史完整时跳过历史 SIP 请求，非
  Alpaca 路由仍保留近期刷新以取得当前数据；
- 明确勾选的分钟增量更新回看最近 5 个自然日并按主键覆盖写入；
- 正常交易周通常至少覆盖最近 2 个交易日，可修正未完成 K 线和迟到数据；
- 分钟导入截止到当前 UTC 时间约 16 分钟前，并保留分钟精度；
- 美股常规交易时段额外批量读取实时 IEX snapshot，将当天 daily bar 作为未收线 K 线写入；
  收盘延迟窗口结束后再由完整 SIP 日线覆盖，避免免费 SIP 15 分钟限制导致开盘初期缺 K 线；
- 若检测到分钟库没有从该标的已核验分钟起点开始的完整历史，勾选分钟更新时会从该起点
  初始化；BTC/USD 的 Alpaca 分钟起点为 2021-01-01，不会再误报缺少 2020 年分钟数据；
- 数据写入采用 UPSERT，可安全重复执行。

### 4.4 Alpaca 限流与并发

- 进程级安全上限为 150 次/分钟；
- 请求会读取 Alpaca 返回的限流响应头，接近剩余额度时主动等待；
- 单页最多 10,000 根；
- 批量历史导入网络并发最多 2 个 worker；
- 分钟数据库写入由进程内锁串行化；
- 总览中的 Twelve Data 免费批量请求每轮最多处理 8 个供应商代码；
- 日线补数和正式事件行情由进程级请求协调器调度：同一标的、同一起点的同类在途请求复用
  一个结果；同时最多执行两个数据任务，手动更新与低优先级总览合计最多占一个槽位，为正式
  决策保留通道；
- 免费延迟行情按约 15 分钟延迟使用，代码额外保留约 1 分钟缓冲。

诊断接口只读取 Alpaca，不写数据库：

```text
GET /api/alpaca/stock-bars?symbol=GLD&timeframe=1Min&start=2020-01-02&end=2020-01-03&feed=sip&limit=1000&max_pages=1
```

`max_pages` 默认是 `1`，用于避免诊断请求意外下载多年数据。响应包含分页状态和 Alpaca
限流响应头解析结果。

## 5. 分钟数据、聚合与时区

### 5.1 存储和展示时区

- Alpaca 原始分钟时间转换为 UTC epoch minute 存入分钟数据库；
- 分钟 K 线展示和日线重建转换为 `America/New_York`；
- Python `zoneinfo` 自动处理 EST（UTC-5）与 EDT（UTC-4）；
- 分钟图仅使用美东常规交易时段 `09:30 <= time < 16:00`；
- 从分钟数据生成的日线日期是美东交易日；
- 行情总览的“更新时间”在前端转换为 `Asia/Shanghai` 显示；
- 普通日线只有交易日期，不保存盘中时刻。

分钟库会保存 Alpaca 返回的盘前盘后数据，但当前图表聚合和日线重建只使用常规交易时段。

### 5.2 聚合规则

- 分钟周期以美东交易日和 09:30 开盘为锚点分桶；
- `1h`、`4h` 和自定义分钟 K 都从 1 分钟原始数据即时聚合；
- `3D` 按连续日线行数聚合；
- `1W` 按 ISO 周聚合；
- `1M` 按自然月聚合；
- OHLCV 规则为首根 Open、最高 High、最低 Low、末根 Close、成交量求和。

美股/ETF 的日线与日线聚合周期按界面选择应用公司行动复权；分钟图先按交易日聚合后使用
同一日级因子，避免同一交易日内因子不一致。原始 K 线始终保留在数据库中，不回写改造。
回测成交和账户盯市使用原始价格，技术指标使用截至当时可知的拆股/分红复权历史。
详细口径与全标的审计见
[公司行动与价格口径](docs/corporate_actions.md)。

### 5.3 实时决策

实时决策模块根据已有历史回测策略创建独立任务，只输出人工辅助信息，不自动下单：

- 总览页支持创建、运行、终止、删除任务；卡片显示状态、运行时长和成功发送数。
- 点击任务后默认打开实时数据面板。面板的展示集合始终是当前行情总览中的全部标的，
  价格与更新时间只读取内部数据库，每 60 秒轮询一次；“重新计算”也不会调用外部行情 API。
- 面板按任务策略自己的市场、观测构造、参数、过滤和排名方式，用内部数据库最新行情模拟“如果
  当前时点决策会看到什么”。它不是正式决策，也不要求等到策略预定事件才显示；策略可以
  使用完整日线、盘中价或自行构造当前观测，因此其“策略 WTME/ATR”等数值与行情页标准
  指标不同是正常且可解释的。股票 IEX/SIP 与加密数据来源的差异会写入审计信息。
- 标的名前的蓝点表示它属于当前任务的正式候选池。任务运行时按 run 不可变快照判断，
  停止时按任务快照判断；蓝点只是提示，不会把行情总览标的加入正式决策。
- 面板支持搜索、状态筛选、仅看候选池、动态指标列排序和行级计算明细；点击标的名称可复用
  行情详情查看 K 线，详情返回按钮会回到当前任务的数据观察面板。较长的行级明细在自适应
  弹窗中展示。代码策略的列由策略代码定义：七星展示长期年化趋势、R²、短动量、可选量比
  和评分；ATR 展示 N 日价格位移、ATR 和评分；WTME 展示 Rw、Aw 和评分。列标题问号会按
  任务当前生效参数说明回看天数、计算口径、用途和关键过滤阈值。
- 任务总览采用紧凑四列卡片。竞争策略会基于行情总览内部数据展示最多三个当前合格标的，
  按评分用金、银、铜三色标记；非竞争策略不显示推荐。
- 非代码策略创建实时任务时自动生成受限 JSON 面板脚本，single、distribution、competition
  均适用，过滤和评分都不是必填的通用前提。脚本可在任务运行中独立校验、保存或恢复自动
  生成版本，只控制展示列，不改变正式规则、候选池、邮件或交易建议。
- 任务保存策略快照；勾选“自动跟随源策略”时，停止后或下一次启动前同步最新策略。
- 所有运行实例由一个可唤醒的中央调度线程管理；普通等待状态不占用事件工作线程，也不
  获取标的行情。只有 OPEN、CLOSE 或策略指定的 `HH:MM` 事件到达时，才向事件线程池提交
  一次决策并调用 Alpaca 股票 IEX 或 Crypto 接口。该正式事件取数不受行情总览自动更新开关影响，且只处理任务
  候选池及代码策略声明的辅助标的。
- 任务启动和每个正式事件都会按策略实际回看长度，核对候选池及辅助标的在事件日前所需的
  每一个已完成交易日。非总览标的和 BTC/USD 同样会按需补数；补数后仍缺日、存在未完成
  历史 K 线，或任一候选没有有效事件行情时，本次正式决策失败关闭，不再用部分候选池重新排名。
- 分钟事件只接受事件前最新完整分钟，若该分钟数据滞后超过 5 分钟则拒绝决策。历史来源、
  截止日、更新时间、数据指纹以及事件信号价/时间写入事件 calculation 日志，邮件正文不
  额外添加这些审计字段。
- 普通等待状态点击终止会立即停止；关键事件已开始获取行情、计算或提交邮件时进入“终止中”，
  本次事件完整收尾后自动停止，且不会再安排后续事件。
- `OPEN` 使用上一交易日完整收盘，分钟事件使用上一根完整分钟，`CLOSE` 必须取得完整日线；
  行情缺失时拒绝补算并记录原因。
- 首次启动会幂等创建一个停止状态、关闭邮件、跟随源策略的“七星ETF轮动实时决策（小池）”
  任务。七星小池和大池回测预置使用同一策略类、代码版本和默认参数，只是标的池与描述不同；
  内置实时任务只使用小池。用户软删除后不会在下次启动时复活。
- 邮件支持 QQ SMTP 和 Gmail SMTP。QQ 可在 `.env` 配置：

  ```env
  QQ_ADDRESS=your_qq@qq.com
  QQ_AUTHORIZATION_CODE=your_authorization_code
  REALTIME_MAX_WORKERS=4
  REALTIME_EVENT_GRACE_SECONDS=60
  ```

  授权码只会加密保存到数据库，接口不返回明文；普通通知按任务至少间隔 1 分钟，网络临时
  失败按退避策略重试。邮件通道表示发件身份，收件邮箱表示通知目标；两者可以填写同一个
  地址。详情页可发送通道测试邮件，测试收件地址默认为当前通道发件地址。
- 非代码策略正文模板使用只读文本占位符：`{{task.name}}`、`{{decision.date}}`、
  `{{decision.time}}`、`{{decision.time_label}}`、`{{decision.datetime}}`、
  `{{decision.actions}}`、`{{decision.basis}}`、`{{decision.summary}}` 和
  `{{message.generated_at}}`。占位符必须原样填写，不能在双大括号内放自定义字符串、数字或
  计算式；固定内容直接写在占位符外。邮件是纯文本，因此所有替换结果最终也是文本，数值
  会先格式化，所有小数最多保留三位。旧的 `event`、`event.name`、`date`、`decision`、
  `basis`、`summary` 别名继续兼容已有任务；未知名称或未闭合的大括号会在保存时直接报错。

完整设计、数据口径、审计字段和运行建议见
[实时决策模块文档](docs/realtime_decision.md)。

## 6. 双数据库设计

数据库文件：

```text
data/market_data.sqlite
```

Schema：

```text
database/schema.sql
```

### 6.1 主数据库 `market_data.sqlite`

主数据库保存业务配置、日线、指标和分析快照。

| 表 | 作用 | 关键字段或约束 |
| --- | --- | --- |
| `symbols` | 标的主数据和界面设置 | `symbol` 唯一；总览显示、顺序、是否显示美股休市日、Alpaca 能力 |
| `daily_prices` | 标的原生日线 OHLCV | `UNIQUE(symbol, date)`；数据源、原周期、完整状态 |
| `daily_price_series` | 策略专用命名日线序列 | `UNIQUE(symbol, series_code, date)`；BTC 的 `US_EQUITY_SESSION` 与原生 24/7 日线隔离 |
| `instrument_symbols` / `instrument_identifiers` | 标的身份沿革 | CUSIP/ISIN 与新旧代码的有效期映射 |
| `corporate_actions` / `corporate_action_legs` | 公司行动 | 事件公共字段及 source/target/acquirer 等参与方 |
| `symbol_aliases` | 多数据源代码映射 | `common_symbol` 唯一；显示、Yahoo、Twelve Data 代码 |
| `api_request_logs` | 数据源调用日志 | provider、symbol、状态、错误码、消息 |
| `indicators` | 全局指标定义 | 指标类型和参数组合唯一 |
| `symbol_chart_views` | 标的可用 K 线视图 | `UNIQUE(symbol_id, view_code)` |
| `symbol_indicators` | 每个视图的指标配置 | 颜色、显隐、顺序；每视图同一指标唯一 |
| `trendline_analysis_snapshots` | 趋势线完整结果和总览摘要 | 标的、周期、算法版本、数据指纹联合唯一 |
| `realtime_decision_tasks` | 实时任务与展示配置 | 正式策略快照、通知、`panel_settings_json`、独立 `panel_revision` |
| `realtime_task_seed_state` | 内置实时任务种子 | 保证七星小池任务只创建一次，软删除不复活 |
| `system_settings` | 服务级小型配置 | 行情总览共享自动更新开关等 JSON 值 |

升级旧数据库时，迁移会先把历史 `nyse_session_derived_1m` 行复制到
`daily_price_series/US_EQUITY_SESSION`。若 BTC/USD 在行情总览中，下一次启动同步会从首个
旧混合行开始重新获取原生 24/7 日线，成功覆盖后不再重复全量修复；手动勾选分钟更新也会
执行同一原生日线修复。

关键字段说明：

- `symbols.alpaca_supported`：`NULL` 未检测、`1` 支持、`0` 不支持；
- `symbols.show_in_overview`：决定是否显示并参与自动行情更新；
- `daily_prices.source_provider`：如 `alpaca`、`yahoo`、`twelvedata`；
- `daily_prices.source_timeframe`：原始周期，分钟派生日线使用 `derived_1m`；
- `daily_prices.is_complete`：标记当前日线是否完整；
- `daily_prices.price_basis`：`raw`、`split_adjusted`、`total_return_adjusted` 或
  `unknown`，复权前必须核验；
- `trendline_analysis_snapshots.payload_json`：完整分析结果；
- `trendline_analysis_snapshots.summary_json`：行情总览使用的紧凑摘要。

### 6.2 分钟数据库 `intraday_data.sqlite`

分钟数据库专门保存大体量原始分钟历史和少量同步元数据。

| 表 | 作用 | 关键字段或约束 |
| --- | --- | --- |
| `intraday_instruments` | 分钟标的字典 | 整数 ID、唯一 symbol、交易所时区 |
| `minute_bars` | 1 分钟 OHLCV | `(instrument_id, minute_utc)` 复合主键 |
| `minute_sync_state` | 每个标的同步状态 | 覆盖范围、行数、状态、最近成功和错误 |
| `import_jobs` | 分页导入及断点续传 | 起止时间、page token、页数、行数和任务状态 |
| `monthly_fingerprints` | 月度轻量质量快照 | 行数、首末分钟、16 字节摘要 |
| `market_sessions` | 交易日历元数据表 | 开闭市 UTC 分钟和早收市标记；当前预留 |

`minute_bars` 字段：

| 字段 | 说明 |
| --- | --- |
| `instrument_id` | 对应 `intraday_instruments.id` |
| `minute_utc` | UTC epoch minute |
| `open_scaled` / `high_scaled` / `low_scaled` / `close_scaled` | 价格乘 `1,000,000` 后存整数 |
| `volume` | 成交量整数 |
| `trade_count` | 成交笔数，可为空 |
| `vwap_scaled` | VWAP 缩放整数，可为空 |

压缩和并发策略：

- 价格使用百万分之一缩放整数，避免重复存储浮点文本；
- `minute_bars` 和多个元数据表使用 `WITHOUT ROWID`；
- SQLite page size 为 8192；
- 使用 WAL、`synchronous=NORMAL` 和 30 秒 busy timeout；
- 分钟写入使用单独的可重入锁；
- 月度指纹用于低成本校验，不复制分钟数据。

## 7. 指标系统

当前支持：

- `MA`：简单移动平均；
- `EMA`：指数移动平均；
- `ATR`：真实波幅的 Wilder 平滑绝对 ATR，首值为前 N 个 TR 的算术平均，随后按
  `ATR(t) = (ATR(t-1) × (N-1) + TR(t)) / N` 递推；
- `相对 ATR`：与“急跌回避与 ATR 动量轮动”一致的有符号评分，日线第 t 根计算为
  `(Close(t) - Close(t-N)) / WilderATR(t-1, N)`。分母只使用前一根已完成日线可知的 ATR，
  不把当前日高低价泄漏进实时决策口径；
- `R²`：复用七星策略的一致加权口径。窗口 N 表示前 N 根完整 K 线加当前价格，
  共 N+1 个节点；对数价格按近期更高的 `q=w²` 权重拟合时间直线，输出 `[0,1]`，默认 N=25；
- `WTME`：加权真实波幅动量效率，可配置窗口、半衰期和 epsilon；
- `RSI`：Wilder 相对强弱指标，默认周期 14，副图固定使用 0～100 并标出 30/70；
- `MACD`：默认快线 12、慢线 26、信号线 9，展示 DIF、DEA 和未加倍柱状值
  `DIF - DEA`；
- `急跌过滤`：近 N 个连续收盘变化段中任一跌幅小于等于负阈值时输出 `1`，否则输出
  `0`。最后一根未结束 K 线也参与最新变化段判断；
- 普通指标周期范围 2～500，急跌过滤观察段数范围 1～500、阈值范围 0.1%～50%；
- 默认收藏 `EMA8`、`EMA13`、`MA20`、`ATR14`、`相对ATR14`、`R²`、`WTME40(h=15)`、
  `急跌过滤5日5%`；
- RSI 和 MACD 不会自动加入收藏；创建后可由用户自行收藏；
- 每个标的的每个 K 线视图最多同时设置 10 个指标；
- 指标配置、颜色、显隐和顺序按“标的 + 视图”保存；
- 标准指标只有一套服务端实现；行情总览和详情序列都调用该实现，浏览器不再另算公式。
  指标基于当前视图的聚合 K 线和所选价格口径重新计算，数据不足时不绘制对应线段；若输入
  包含未收线 K 线，也会计算最新暂定值并携带 `is_provisional`、`as_of`、`price_basis` 和
  指标契约版本，后续行情更新可使其变化。ATR 与相对 ATR
  使用独立副图，分别使用左、右刻度，避免改变主图价格比例；
- 行情总览不显示周/月涨跌，表头固定提供三个自定义日线指标下拉列；空选项显示空列，
  非空选项从收藏指标中选择，并在单元格提示公式、前复权口径、数据日期和盘中状态。

各场景的输入口径明确分层：

| 场景 | 指标/策略输入 | 未收线处理 |
| --- | --- | --- |
| 行情总览标准指标 | 本地已存公司行动前复权后的日线 | 纳入当前暂定日线，悬停提示尚未收线 |
| 行情详情标准指标 | 当前周期、当前所选复权方式的 K 线 | 纳入当前暂定 K 线并在图例标记 |
| 历史回测/正式实时决策 | 策略在该事件时点允许看到的数据 | 禁止未来数据；是否及如何构造当前观测由策略决定 |
| 实时任务观察面板 | 任务策略使用内部数据库最新行情模拟当前时点 | 显示策略值，不冒充行情页标准指标或正式决策 |

## 8. 智能趋势线分析

智能分析目前只支持 `1D`、`3D`、`1W`、`1M`，默认分析最新 150 根 K 线。它寻找的是
上涨行情下方的支撑线和下跌行情上方的压力线，而不是价格回归中轴。

主要行为：

- 后台分析行情总览中的标的；
- 快照按算法版本、周期、窗口、是否显示美股休市日和数据指纹复用；
- 冷计算最多使用 4 个进程，并至少为 Flask 和行情更新保留 1 个逻辑 CPU；
- 子进程只读行情并计算，主进程串行写入 SQLite；
- 单个标的失败不会中断整批；
- 输出短期、中期、长期结构，以及趋势中、挑战中、已结束状态；
- 每个趋势族最多保留一条主线和一条具有独立证据的阶段线；
- 最终最多展示 6 条趋势线；
- 总览摘要显示点位和最新事件，评分细节放在悬浮层。

核心算法包括 ATR 归一化、单侧包络拟合、多触点确认、实体穿越过滤、触点分布评分、
跨层级几何去重和趋势族筛选。

详细说明：

- [完整算法文档](docs/trendline_algorithm_complete.md)
- [简明设计与案例](docs/trendline_algorithm.md)

## 12. 当前边界

- 分钟历史仅支持 Alpaca 可识别的美股和 ETF；
- 不在行情总览中的标的不会自动更新，但可以手动查询或更新；
- 总览自动同步不下载或增量更新分钟历史；
- 趋势线智能识别暂不支持分钟周期；
- 回测支持拆股动态复权和现金分红；行情详情可切换原始/拆股/全复权，总览标准指标固定使用
  基于本地已存公司行动的前复权口径；
- 分钟图和分钟派生日线只使用美东常规交易时段；
- 回测使用官方交易日历缓存；现有 K 线聚合流程仍沿用自身常规交易时段逻辑；
- 回测不模拟订单簿、部分成交、市场冲击、税费和融资利息；固定滑点需由使用者保守设置；
- 数据库浏览器只分页展示主数据库，分钟库通过质量脚本检查；
- 系统定位为本机单用户应用，不应直接暴露到公网。
