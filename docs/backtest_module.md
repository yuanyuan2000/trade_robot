# 历史回测模块设计、使用与审计说明

本文说明历史回测模块的界面、策略模型、成交时点、账户计算、数据约束、API、测试方法和
已知边界。实现以 `services/backtest/`、`database/backtest_repository.py` 和
`static/js/backtest.js`、`static/js/backtest_analysis.js` 为准。

## 1. 模块结构

历史回测是与“查看行情”“智能分析”并列的独立栏目。

- 策略列表支持新建、打开、重命名、修改、保存、复制和永久删除。
- 前端只创建非代码策略，并在创建时固定 `single`、`distribution`、
  `competition` 选标模式。代码模式只能由开发者在项目代码中注册。
- 首次使用会一次性写入三个真实行情测试策略、内置的“急跌回避与ATR动量轮动策略”，
  以及“七星ETF轮动策略”的小池/大池两个预置。用户删除后不会在下次启动时复活。
- 工作区左侧是策略设计，右上是指标与资金曲线，右下是运行日志。
- 页面右上“回测结果”进入跨策略运行总览；列表包含编号、回测时间、策略、回测区间、
  标的、杠杆、状态、收益、最大回撤和成交数。点击记录进入只读快照，不会混入该策略的
  其他运行；右上角“查看设置”沿用正常回测设置弹窗，但所有字段和保存按钮均为只读。
- 资金曲线鼠标十字线显示日期、权益、现金、累计收益和按市值计算的标的仓位比例；左右
  坐标分别显示十字线对应的资金与收益率。
- 运行设置随策略保存；再次打开策略时恢复上次保存的设置。
- 每次运行保存不可变的策略 revision、完整策略快照、运行设置和行情数据指纹。以后修改
  策略不会改写旧运行。
- 新运行同时保存一行不可变的参数摘要；查看历史运行时显示该摘要。代码策略通过
  `describe_run()` 在代码中定义表述，非代码策略自动记录标的、启用规则、条件和动作。
  功能上线前没有摘要的旧运行保持空白，不根据后来修改过的策略反推。
- 回测在单 worker 后台队列执行，页面通过 SSE 接收每日权益、成交和日志增量。运行中可
  取消；应用不会因浏览器心跳消失而自动关闭正在执行的回测。
- 后台 worker 使用专用 `backtest` 线程，但与 Flask 请求线程共享同一 Python 进程。运行进度
  采用增量同步，实时指标按 0.5% 进度步长最多重算约 200 次，并在每日进度边界主动让出执行权；分析
  区间请求不复制决策日志，只有指定日期的决策接口读取当天日志，以降低长回测对其他页面的
  GIL 和内存锁竞争。单 worker 也保证多个回测不会同时争抢本地行情与 SQLite。
- 每个策略保存 `market` 契约。当前仅支持 `US_EQUITY`，其日历固定为 `XNYS`、时区固定为
  `America/New_York`，不能把市场类型、日历和时区拼成不一致的组合。界面已经保留市场选择
  入口，以后增加加密或 A 股时扩展同一契约。

### 1.1 精细化分析

收益曲线下方的“精细化分析”进入同一次运行的独立分析工作区：

- 可选择 1、3、6、12 个月周期，或在已完成交易日范围内指定起止日期，并用上一/下一周期
  快速平移。运行中从首个权益点起完成三个自然月后开放，SSE 推进时动态扩展可选终点；终态
  运行即使不足所选周期，也按实际首尾日期展示。
- 区间曲线都以各自首个可用收盘点为 0%，包括策略权益、资产池每个标的单独买入持有、资产
  池等权，以及不在资产池内的显式基准。`auto` 就是等权线；显式基准已在资产池时只标注对应
  资产线，不重复生成。每条线使用不同颜色，图例支持逐条开关和批量显隐。
- 鼠标日期联动决策面板。代码竞争策略和可视化竞争策略按评分降序显示标的、过滤状态、评分、
  代入值后的最后一步公式，数值最多四位有效数字；七星策略公式帮助为“评分 = 长期年化趋势 ×
  R²”。可视化非竞争策略显示规则内容、代入后的条件和执行结果。
- 原始价格日 K 仅用于展示，可在资产池标的间切换；买点使用 K 线下方蓝色 B 箭头徽标，卖点
  使用 K 线上方橙色 S 箭头徽标，避免与红绿 K 线混淆。区间成交汇总买入数、卖出数、盈利
  卖单数、卖出实现盈亏、手续费和区间标的收益率；收益率口径为“（卖出实现盈亏－区间手续费
  －区间滑点）÷ 区间起始日总权益”。逐笔成交的已实现盈亏金额按正数绿色、负数红色显示。
- 曲线由运行快照、现有日线和公司行动清单按请求实时计算，只使用小型进程内 LRU 缓存；没有
  `backtest_comparison_points` 或其他新增持久化表。删除历史运行时同步清除该运行的分析缓存。

### 1.2 市场日历与日线序列

- 美股策略只在 XNYS 实际交易日运行；周末和元旦、圣诞节等休市日不进入任何日线指标窗口。
- `OPEN`、`CLOSE` 和具体时间均使用美东时间，夏令时及提前收市使用保存的交易日历分钟。
- 股票/ETF 使用 `daily_prices` 原生日线。BTC/USD 的 24/7 原生日线仍保存在
  `daily_prices` 供行情页使用；美股策略改读 `daily_price_series` 中独立的
  `US_EQUITY_SESSION`，该序列由 BTC 分钟线按当日 XNYS 常规时段重建。
- 两类日线不会互相 UPSERT 覆盖。旧库中标记为 `nyse_session_derived_1m` 的 BTC 行会在迁移
  时复制到命名序列；之后重新获取原生 BTC 日线不会改变历史回测使用的会话序列。
- 日线历史起点与分钟历史起点分别保存。具体分钟策略只能从“日线预热完成日”和“已核验分钟
  起点”两者较晚者加入；引擎按实际预热参数写入例如“BTC/USD从2021年X月X日加入回测”的
  INFO 日志。

## 2. 非代码策略

### 2.1 选标模式

| 模式 | 行为 |
| --- | --- |
| `single` | 只能配置一个标的，规则控制该标的仓位 |
| `distribution` | 多个标的独立执行同一组规则；每个标的有单独上限，所有上限之和不得超过 100% |
| `competition` | 同一时点对合格标的评分，只买最高分标的；换仓时先卖后买；可设置无合格标的时清仓 |

`competition` 的普通规则是可选的，只承担 HOLD 或风险退出，不能直接 BUY；没有额外风控
时可以保持规则列表为空。候选条件和评分公式在竞争配置中单独设置。评分相同时按标的代码
排序，保证结果可复现。
若当前持仓命中普通规则，该规则在本事件优先执行，竞争换仓推迟到下一次竞争事件，避免
HOLD 或部分 SELL 被自动换仓订单覆盖。

候选条件可以早于评分时间检查，并把当日通过结果保存到评分时点。例如 09:50 用
`rapid_drop(5, 5) = 0` 固化急跌过滤，10:00 再按 WTME 评分。可选的“最低可入选评分”采用
包含边界；设为 `0` 表示负分标的全部淘汰。无标的同时通过候选条件和最低评分时，“无合格
标的时空仓”决定清仓还是保持原仓位。“胜出标的不变时再平衡”关闭后，仅在目标发生变化时
交易，可与内置轮动代码策略保持一致。

### 2.2 规则优先级

每条规则包含：

```text
[BUY | SELL | HOLD] [TARGET | DELTA] [0..100]%
IF [condition]
WHEN [OPEN | CLOSE | HH:MM]
```

- 规则按优先级升序执行；同一标的、同一时点采用第一条命中的规则。
- `HOLD` 不下单，并停止检查该标的在该时点的后续规则。
- `TARGET 60` 表示把仓位调整到总权益的 60%。
- `DELTA 10` 表示增加或减少 10 个百分点，而不是当前仓位的 10%。
- 规则名称是系统根据动作和条件自动生成的日志说明，不属于公式语法，因此不在规则编辑
  行中单独显示。
- 买入目标不能超过该标的上限，卖出目标不能低于 0；不合法订单记 ERROR 并使运行失败，
  不会静默裁剪。

### 2.3 公式语言

公式支持：

- 布尔：`AND`、`OR`、`NOT`、括号、`true`、`false`
- 比较：`>`、`>=`、`<`、`<=`、`=`、`!=`
- 算术：`+`、`-`、`*`、`/`
- 当前量：`price`、`position`
- 已完成日线：`open(n)`、`high(n)`、`low(n)`、`close(n)`、`volume(n)`
- 指标：`ma(n)`、`ema(n)`、`atr(n)`、`ratr(n)`、`r_square(n)`、`rsi(n)`
- MACD：`macd_line(fast, slow)` 返回 DIF，`macd_signal(fast, slow, signal)` 返回 DEA，
  `macd_hist(fast, slow, signal)` 返回未加倍的 `DIF - DEA`
- WTME：`wtme(n, h)` 或 `wtme(n, h, epsilon)`
- 急跌过滤：`rapid_drop(n, threshold_percent)`，最近 n 个连续价格变化段任一跌幅达到阈值
  时返回 `1`，否则返回 `0`

`ratr(n)` 等于当前决策价相对 n 个交易日前收盘价的位移除以前一完整交易日可知的 Wilder
ATR(n)。`r_square(n)` 复用七星一致加权 R²，取前 n 根完整 K 线和当前决策价共 n+1
个价格点，对对数价格做近期权重更高的直线拟合并返回 `[0,1]`。WTME 的 `h` 范围为
0.1～500，epsilon 默认 `1e-8`；急跌阈值范围为 0.1%～50%。`position` 是 0～1 的策略
仓位占比。`n` 必须为 1～500 的整数（WTME 和 R² 至少为 2）；`n=0` 被禁止。公式由
AST 白名单解释器执行，不使用 Python `eval`，属性访问、导入、任意函数调用、NaN 和
Infinity 都会被拒绝。

日线函数的 `n=1` 始终表示当前交易日之前最近一个已完成交易日。MA/EMA/ATR 在 OPEN
和具体分钟只使用前一交易日及更早的数据；在 CLOSE 可以包含当日已经完成的日线，但其
订单只能到下一交易日开盘成交。ATR 使用真实波幅和 Wilder 递推。

示例：

```text
price > ma(20) AND position < 0.5
(price - close(5)) / atr(5) > 1.2
close(1) >= ema(20) OR atr(14) < 3
rsi(14) < 30 AND price > ma(20)
macd_hist(12, 26, 9) > 0
wtme(40, 15) >= 0 AND rapid_drop(5, 5) = 0
r_square(25) >= 0.8 AND price > ma(20)
```

盘中计算 `ratr`、R²、WTME 和急跌过滤时，当前观测只使用“前收盘价 → 决策价”这段已知路径，
不会读取当日尚未完成的最高价、最低价或收盘价；CLOSE 时才可使用完整当日日线。指标的
数学定义是固定的，但策略有权决定向指标公式提供哪些点时可知 K 线或自行构造观测，因此
盘中策略值不等同于行情页把当前暂定 OHLC 当作最后一根标准 K 线计算出的指标值。

## 3. 防止未来数据

本模块将“产生信号”和“撮合成交”明确分开：

| 规则时间 | 信号可见数据 | 成交参考价 |
| --- | --- | --- |
| `OPEN` | 前一交易日复权后的收盘价和更早日线 | 当日原始开盘价 |
| `HH:MM` | `HH:MM` 之前最近一根完整分钟的收盘价和前一交易日以前的日线 | 目标时刻起首个可成交分钟的原始开盘价 |
| `CLOSE` | 当日完整收盘数据 | 下一交易日原始开盘价 |

正常连续交易时，10:00 规则只读取 09:59 这一完整分钟的 close，按 10:00 分钟 bar 的
open 撮合，不会读取 10:00 分钟的 high、low 或 close。若停牌或熔断导致目标分钟没有
bar，则信号只使用目标时刻以前最近一根完整 bar，订单按目标时刻以后首根 bar 的 open
成交。这相当于订单在停牌期间排队，不会读取恢复交易后的价格来改变信号。回测最后一天
产生的 CLOSE 信号因为没有下一交易日成交点，会记录 WARN 并丢弃。

所有具体分钟均按 `America/New_York` 解释。系统从 Alpaca 官方交易日历核验交易日、
夏令时和提前收盘；七星策略的卖出/买入事件在提前收市日映射到收市前第 2/第 1 分钟，
其他没有声明映射规则且超出实际交易时段的策略预检失败。如果同一
常规交易时段内既找不到事件前信号 bar，或事件后直到收盘都没有可成交 bar，运行才会
失败。错误信息按标的、起止日期、事件时间及缺少“信号/成交”哪一侧分段列出。
日线必须标记为完整；实际收盘时间尚未过去或延迟行情仍可能未完成的交易日也不能回测。

运行开始前，所需日线和分钟点被载入内存形成固定数据集。之后的策略执行只读取该快照，
并保存每个标的的日线/分钟 SHA-256、交易日历 SHA-256、公司行动 SHA-256 和覆盖范围。

## 4. 代码策略内部接口

硬编码策略继承 `CodeStrategy` 并注册到 `STRATEGY_REGISTRY`，需声明：

- 唯一 `key` 和明确 `version`
- 支持的选标模式
- 默认标的及仓位上限
- 可由前端修改的参数 schema 和默认值
- 所需事件时间和最小日线预热长度
- `on_event(context)` 返回统一的 `OrderIntent`
- 可选的 `observation_columns()`、`observe_latest()` 和 `observation_target_count()`，用于
  实时任务页面以内部最新行情模拟当前时点；这些方法只负责观察展示，不改变 `on_event`
  的回测或正式实时决策语义

代码策略和非代码策略共用相同的数据快照、事件时钟、账户、手续费、滑点、公司行动、
日志和底层标准指标函数。策略仍可自由组合、过滤或构造第三种点时观测；实时观察服务不再
按 `code_key` 硬编码这些中间值。保存的代码版本与当前注册版本不一致时拒绝运行，防止旧
结果无法解释。

内置 `rapid_drop_atr_rotation` v1.3.0：

1. 标的池为 SPY、GLD、NVDA、MU、XLE。
2. 09:40 正常使用 09:39 完整分钟价格；若处于停牌则使用 09:40 前最后一根完整分钟。
   急跌窗口的最后一段固定为“最新完整分钟实时价 / 上一交易日收盘”，此前各段使用完整
   日线。百分比急跌和 ATR 急跌拥有独立开关与阈值；ATR 模式使用每段下跌发生前可得的
   Wilder ATR，不引入未来日线。
3. 10:00 正常使用 09:59 完整分钟价格；所有候选（包括被硬过滤者）均计算并记录
   `（当前价 - N 个交易日前收盘）/ ATR(M)`。过滤后按分数选择前 `holdings_num` 只，
   每只目标仓位为“总目标仓位 / holdings_num”；合格标的不足时，空缺份额保留现金。
   目标标的不变时继续持有，不因杠杆导致的仓位比例漂移而每日重复再平衡。
4. 持仓数量最小为 1 且不得超过候选数；风险检查时间必须早于轮动时间，候选单标的上限
   不得低于等权目标。时间、开关与数值参数均在保存时验证。
5. ATR 加权可选 Wilder、EMA、线性加权或简单等权。Wilder 为兼容旧结果的默认值；EMA
   对近期波动响应更快，适合作为轮动策略的推荐选项；线性加权仅使用最近 N 个 TR，近期
   权重从 `1` 线性增加到 `N`，更易解释。所选口径同时用于动量评分和 ATR 急跌过滤。

完整参数、逐段急跌公式、四种 ATR、排名/仓位细节、当前数据库配置差异、限制与改进建议
见 [急跌回避与 ATR 动量轮动策略说明](rapid_drop_atr_rotation.md)。

内置 `sevenstar_etf_rotation` v1.1.0 提供小池和大池两个独立预置。它使用近期加权对数回归，
并以 `q=w²` 统一回归有效重要性、残差平方和、总平方和及加权中心。近恒价序列返回全零，
R² 保持在 `[0,1]`；指数年化改用 `expm1`，极端正趋势有限饱和，所得评分仍接受最高评分阈值检查。
第一阶段修复仍保留指数年化评分，同时增加 `non_positive_trend` 非正长期趋势保护。参数
“长期趋势公式”默认使用该一致模式，也可明确切换到“历史 v1.0.0 不一致权重”以复现旧
R²、普通均值和双负正评分语义；历史模式不执行 `non_positive_trend`。策略叠加
高点回撤、放量过热、短期动量和近三日急跌过滤，14:00 缓存排名、14:00 先卖、14:01 后买，
无候选时转入 BIL。完整池、公式、严格
边界、全部前端参数、晚成立资格和数据导入说明见
[七星 ETF 轮动策略说明](sevenstar_etf_rotation.md)。

## 5. 账户与撮合

### 5.1 基本假设

- 账户基础货币为美元。
- 只支持多头现货，不允许卖空。运行设置可选择 1–10 倍账户杠杆；杠杆买入形成的融资以
  负现金表示，第一版不计融资利息，比较基准始终保持 1 倍。
- 默认只交易整数股；开启碎股后数量精确到 `0.000001` 股。资产可声明更严格的专用步长，
  BTC/USD 固定为 0.0001 BTC。
- 新策略默认结束日期为应用所在机器当前日期的前一天，每股手续费为 0.01 美元、每笔
  最低手续费为 1 美元、年化无风险利率为 0.045（4.5%）。
- 同一时点的卖单先于买单，换仓资金可在同一事件中使用。
- 所有核心金额和持仓使用 Python `Decimal` 计算，输出/持久化时才转换为 JSON 数值。

### 5.2 手续费与滑点

每一笔订单：

```text
commission = max(quantity * commission_per_share, minimum_commission)
buy_fill   = reference_price * (1 + slippage_bps / 10000)
sell_fill  = reference_price * (1 - slippage_bps / 10000)
buy_cash   = old_cash - quantity * buy_fill - commission
sell_cash  = old_cash + quantity * sell_fill - commission
```

最低手续费按订单收取，不按日汇总。滑点同时进入成交价、现金、成本基础、已实现 PnL 和
`total_slippage`。目标仓位数量采用包含手续费和滑点的二分求解，确保成交后的仓位仍不
超过目标或标的上限；整数股向可执行方向取整。

### 5.3 成本和盈亏

- 买入 lot 的单位成本包含买入手续费。
- 卖出按 FIFO 消耗 lot。
- `realized_pnl = 卖出金额 - 卖出手续费 - 被消耗 lot 的含费成本`。
- 未实现盈亏使用收盘盯市价减剩余 FIFO 成本。
- 每日总权益满足：

```text
equity = cash + dividend_receivables + Σ(quantity * close_price)
```

回撤峰值从初始资金开始，避免首个收盘已经亏损却被当作零回撤。

### 5.4 杠杆与爆仓

账户 `leverage_multiplier` 和各标的 `definition.symbols[].leverage_multiplier` 均默认 1，
单个标的的最终有效杠杆为二者乘积。策略目标仓位仍使用 0%–100% 语义；例如整体 2 倍、
标的 3 倍时，目标 50% 对应 300% 实际敞口。手续费和滑点按放大后的实际成交数量计算，
代码策略和 DSL 读取的 `position` 则按该标的有效杠杆反归一化，避免杠杆改变原策略判断。

账户权益不大于 0 时认定爆仓。引擎在开盘、成交后、策略事件和持仓期间的分钟行情上检查
权益；先以日内最低价判断当日是否存在风险，存在风险时再读取同步分钟数据定位首个爆仓
分钟。分钟 K 线无法还原一分钟内部的逐笔先后，因此检测精度为分钟级。爆仓后按检测价格
强制平掉全部持仓、停止后续信号，保存 `LIQUIDATION` 日志、终止快照、成交和指标。跳空、
手续费或滑点可能使期末权益小于 0、总收益低于 -100%。

任务状态仍为 `completed`，并以 `termination_reason=LIQUIDATED` 区分正常跑完和爆仓结束；
数据预检或程序错误仍使用 `failed`。

### 5.5 拆股和分红

回测通过 Alpaca 公司行动接口核验完整数据范围：

- 正向/反向拆股在除权日开盘前调整数量和每股成本，总成本不变；历史指标按当时已知拆股
  比例动态复权。
- 现金分红在除息日按开盘前持仓确认为应收，在支付日转为现金；支付日在非交易日时于
  下一回测交易日结算。回测结束前未支付的股息仍作为应收计入权益。指标历史使用除息日
  前收盘价计算点时复权因子；同日多笔分红先求和，避免重复乘因子。
- 成交、持仓盯市和权益使用原始 K 线；指标使用截至当前回测日的复权历史。现金分红仍只
  通过应收/到账进入账户，因此不会将复权变化再次计入账户收益。
- 整数股账户遇到会产生零股的拆股时，如果接口没有现金替代金额则停止运行；开启碎股可
  保留该零股。
- 股票分红、合并、分拆、退市等尚未准确建模的公司行动会在预检阶段停止运行。
- 更名按身份事件审计但不改变持仓；合并、分拆等多方事件按参与方角色判断，只有真正受
  影响的 source/acquiree 才阻断，作为 acquirer/target 被接口关联返回时不会误报。
- 拆股缺比例、现金分红缺金额或支付日时采用 fail-closed。系统不会用除息日冒充未知
  支付日；例如已扫描到的 INTC 2020-02-06 分红因缺支付日会明确阻断相关区间。
- 无凭据、网络失败或供应商响应异常时也停止运行，不会假设“没有公司行动”。
- 公司行动成功缓存最多复用 24 小时，之后重新核验整个连续覆盖区间，以发现供应商后续
  补录或修订的数据。

## 6. 比较基准

- `none`：不绘制基准。
- `SPY` / `GLD`：期初按同样的手续费和滑点买入并持有。
- `auto`：资产池等权；单标的池等同于 100% 持有该标的。

晚成立候选在自身预热完成前对应的固定等权槽位保持现金，首次具备资格的交易日开盘买入；
防御标的不进入 `auto`。

基准与策略使用相同初始资金、整数/碎股设置、手续费、滑点、拆股和分红处理。因此基准
不会获得“免费成交”的不对称优势。

### 6.1 执行性能与复杂度

- 每个标的预建有序日期索引，历史值和尾部窗口通过二分定位；`close(n)` 等单点历史函数不再
  构造历史列表，WTME、R²、急跌过滤等有限窗口盘中指标只读取公式真正需要的 `N` 或 `N+1`
  根 K 线。
- 分红和拆股使用按标的、日期累计的价格/成交量因子。原始行日期到当前回测日的点时复权通过
  两个累计因子的比值完成，不再为每一行遍历整份公司行动清单。
- EMA、Wilder ATR、RSI、MACD 等递归指标先将日线转换到公司行动归一化坐标，再按“标的 +
  参数”一次生成序列并复用；回到某个交易日时只需 O(1) 查询及尺度还原，语义与逐日重新复权
  全历史一致。
- 同一个标的/事件的 DSL 函数结果缓存在 `ExpressionContext` 中。策略求值和结构化审计输入
  读取同一结果，不会为了写日志再次执行指标。
- 内置代码策略的历史读取均显式声明固定窗口；ATR 轮动使用一次生成的 ATR 序列。FIFO lot
  使用队列并维护常数时间成本基础。固定资产池和固定指标集合下，引擎主循环总复杂度近似
  O(交易日数)，内存中的权益、成交及可选日志仍随运行长度线性增长。

## 7. 输出指标和日志

曲线保存每日收盘的现金、融资额、总敞口杠杆、应收股息、持仓市值、总权益、累计收益、
回撤、完整持仓快照及基准值；爆仓日保存强平后的终止快照。图表左轴为资金，右轴为累计
收益率。

指标包括总收益、按实际日历天数复合的年化收益、最大回撤及峰谷日期、年化波动率、
Sharpe、Sortino、Calmar、成交数、卖单胜率、平均已实现 PnL、Profit Factor、总手续费、
总滑点、平均敞口、换手率、基准收益、超额收益、设置杠杆、最高实际杠杆和爆仓信息。
第一日日收益从初始资金计算，之后采用
相邻交易日收盘权益；波动和风险比率按 252 个交易日年化。无足够分母时返回 `null`，
不伪造为 0。

页面顶部只保留运行结果、总收益率、年化收益率、最大回撤、Sharpe、Sortino、交易次数和
胜率。SSE 每个进度批次都会刷新这些当前值；尚不可计算时显示“运行中”。总收益率和年化
收益率严格大于零使用绿色、严格小于零使用红色、等于零沿用默认文字颜色。完整指标仍保留
在运行记录和导出中，只是不再全部挤在资金曲线上方。

其中三个容易误读但有意义的指标：

- Sortino：年化超额收益除以下行波动率，只惩罚负收益波动，比 Sharpe 更聚焦下行风险；
  回测很短或几乎没有负收益时会不稳定或没有有效值。
- 胜率：FIFO 口径下，已平仓卖单中已实现 PnL 大于 0 的比例。它不体现赚一笔和亏一笔的
  金额差异，必须结合总收益、Profit Factor 和回撤判断。
- 换手率：所有成交名义金额之和除以平均权益。它衡量资金周转和策略对手续费、滑点的
  敏感程度；数值大并不自动代表好或坏。

日志级别：

运行设置中的 `generate_logs` 默认为 `true`。关闭后引擎不会构造、显示、通过 SSE 传输或写入
`backtest_logs`；运行失败仍通过 `backtest_runs.error_code/error_message` 返回原因。成交、权益、
指标、取消和爆仓行为保持不变。LOG 下载会禁用，XLS 的运行摘要和成交工作表仍可使用，但依赖
日志的策略审计/决策明细为空。实时决策邮件依赖结构化解释，因此正式实时任务始终强制启用日志。

- DEBUG：规则判断、竞争评分、代码策略自定义诊断、每日持仓、浮动盈亏和权益。急跌/ATR
  策略为每个候选记录代入数值后的评分公式、评分、排名和全部硬过滤原因。七星策略
  在每天排名时为每个当日有效候选分别写一条评分日志；即使候选被淘汰，也保留评分、
  R²、年化趋势和命中的全部硬过滤原因，包括 `non_positive_trend`（长期拟合趋势非正）。
- INFO：运行起止、买卖、已实现 PnL、拆股和股息。
- WARN：例如末日 CLOSE 信号无法成交或回测因爆仓提前结束。
- ERROR：数据预检、非法订单、运行错误和触发强平的 `LIQUIDATION` 事件。

页面的 INFO 过滤同时显示 WARN/ERROR，ERROR 只显示错误。日志支持两种下载：

- `LOG`：保持原纯文本格式，便于快速查看和全文搜索；
- `XLS`：包含“运行摘要”“买卖操作”“标的盈亏分析”和“策略自定义日志”四个工作表。摘要记录杠杆倍率、
  终止原因和爆仓时间；买卖表按列拆分时间、标的、
  方向、数量、参考/成交点位、金额、手续费、滑点、已实现 PnL、成交后账户状态和原因；
  盈亏分析表按标的统计全部成交次数、FIFO 已实现盈亏总额，以及最大单次盈利和亏损的
  时间与金额；
  自定义表根据结构化 DEBUG 上下文展开，代码策略可通过新增自定义事件和 context 字段
  扩展列。急跌/ATR 策略使用专用每日矩阵，每个候选各有公式与结果两列，两种急跌规则
  各占一列，并附最终操作、点位、标的及仅卖出时填写的 PnL。七星策略同样使用专用每日
  矩阵，候选评分各占一列，六类过滤规则各占一列，并附排名、
  最终目标、收盘持仓、操作、点位、标的和仅卖出时填写的 PnL。

终态运行可在“回测结果”总览中批量删除。前端要求二次确认，后端还要求请求体明确包含
`confirm=true`。删除后记录不会再出现在普通总览、策略历史或详情接口；数据库实际删除
`backtest_logs` 和 `backtest_equity_points`，保留带 `deleted_at` 的隐藏运行摘要、不可变
策略/设置快照、指标和成交，以便未来实现摘要级恢复。该操作当前没有用户端撤销入口。

## 11. 边界

回测是基于明确成交假设的确定性模拟，不可能仅靠 OHLC 数据复原真实订单簿。当前不模拟
限价单、部分成交、成交量冲击、bid/ask spread、税费、汇率、融券、融资利息
或券商特有的零股现金替代规则。固定滑点用于显式表达这些交易摩擦的一部分；使用者应按
标的流动性设置保守滑点并做敏感性测试。

生产运行要求本地日线完整；预检遇到缺失或不完整数据时会停止在第一个问题，并在错误
消息和结构化 `detail` 中返回具体标的、缺失日期和问题类型。具体分钟策略要求每个事件
在常规交易时段内同时能找到事件前信号 bar 和事件后可成交 bar。七星策略的防御标的
BIL 允许完全无数据，此时保持现金；一旦存在本地历史，其历史起点之后仍严格检查。
交易日历和公司行动首次覆盖新区间时需要可访问 Alpaca，之后可使用已核验缓存。
任何无法证明正确的数据情况均采用 fail-closed：停止回测并输出错误，而不是生成可能
错误的收益曲线。

列出所支持行动类型并提示数据可能延迟产生；
[Alpaca 美股交易日历](https://docs.alpaca.markets/us/reference/legacycalendar)
提供交易日、开收盘时间和提前收盘信息。供应商尚未发布的信息无法由本地系统提前得知，
这是任何历史行情回测都无法完全消除的外部数据边界。
