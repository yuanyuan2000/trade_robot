# A 股行情、回测与实时决策接入方案

调研与本机 POC 日期：2026-08-23

## 1. 结论

推荐把 **TdxQuant 作为 A 股主数据源，AKShare 作为按能力降级的备用源**。当前不需要 key，也不需要直接解析通达信的二进制文件。

本机 POC 已确认：沪、深、北代码表，2020 年以来日线，5 个目标基金的盘后 1 分钟线，批量最新价、单标的快照、公司行动、复权结果和历史交易日均能经 `127.0.0.1:17709` 读取。项目现有“查询标的—选择是否包含分钟—后台写入 SQLite”的交互可以保留，只需把数据获取层从美股专用实现改成按 `market=CN` 路由。

能力边界必须明确：

- 5 个目标基金的分钟文件不是“100 个交易日”，而是最近约 100 个自然日，即 **70 个交易日、每个交易日 240 根**，当前范围为 2026-05-15 至 2026-08-21。这个区间可以做严格分钟回测；SQLite 每日增量留存后，范围会持续增长且不会随通达信滚动窗口丢失。
- TdxQuant 的 `get_market_data('1m')` 是盘后分钟历史；官方明确说明盘中暂只支持日 K。因此它不能直接返回正在形成的、带供应商时间戳的 1 分钟 K。
- `get_pricevol`、`get_market_snapshot` 和 `subscribe_hq` 能提供实时行情链路。对当前急跌/WTME 策略，公式只需要 09:50 和 10:00 的点时价格，不需要当日分钟 OHLC，所以可以设计为“事件前后实时快照”而不降低策略公式。但交易时段内的时效、回调间隔和断线表现仍须做一次工作日验收；周末只能证明接口、订阅和缓存链路可调用。
- 如果将来某策略硬性要求“上一根交易所官方完整分钟 K”，TdxQuant 当前不能单独满足，届时需接入带时间戳实时分钟 K 的券商/商业源。自行每 6 秒采样只能形成观测 K，不能宣称是官方分钟 K。
- AKShare 能覆盖沪深京日线、实时行情、近期分钟线和分红配送，但东财 1 分钟接口只有近 5 个交易日且不复权。备用切换必须按数据类别和验收状态执行，正式决策默认失败关闭，不能把展示级备用行情静默当成交易级行情。

### 2.1 目标池日线与分钟线

5 个目标基金的日线均从 2020-01-02 延续到 2026-08-21：

| 标的 | 日线条数 | 1 分钟条数 | 分钟交易日 | 分钟范围 |
| --- | ---: | ---: | ---: | --- |
| `518880.SH` | 1,609 | 16,800 | 70 | 2026-05-15 至 2026-08-21 |
| `161226.SZ` | 1,607 | 16,800 | 70 | 2026-05-15 至 2026-08-21 |
| `501018.SH` | 1,607 | 16,800 | 70 | 2026-05-15 至 2026-08-21 |
| `513100.SH` | 1,609 | 16,800 | 70 | 2026-05-15 至 2026-08-21 |
| `159915.SZ` | 1,608 | 16,800 | 70 | 2026-05-15 至 2026-08-21 |

分钟文件位于 `vipdoc/<sh|sz>/minline/*.lc1`，每个文件 537,600 字节；日线位于 `vipdoc/<sh|sz>/lday/*.day`。两种都是通达信私有定长记录。正式接入不直接解析文件，而由 TdxQuant 官方接口读取，这样可以避免版本、市场代码、复权和字段缩放差异。

分钟标签已确认是 **结束时间标签**：上午 `09:31` 至 `11:30`，下午 `13:01` 至 `15:00`。入库时应各减 1 分钟，映射为项目当前使用的 bar 起始时间：`09:31 -> 09:30`、`10:00 -> 09:59`、`13:01 -> 13:00`、`15:00 -> 14:59`。午休不应生成缺口或前值 K 线。

最新交易日分钟汇总与日线的收盘、高低、成交额基本一致，成交量只有极小的末位差异；但 `513100.SH` 的分钟原始聚合开盘/最高与日线不一致。根因不是时区，而是 TDX 在无成交分钟中保存了“成交量为 0、OHLC 沿用前值”的占位 K。2026-08-21 该基金 10:31 才出现首个非零成交，09:50 和 10:00 的占位价仍为前收盘 2.212，而当日实际开盘为 2.195。

70 个交易日中，目标事件分钟零成交的次数如下：

| 标的 | 09:50 零成交 | 10:00 零成交 | 10:00 前整段无成交 |
| --- | ---: | ---: | ---: |
| `518880.SH` | 0 | 0 | 0 |
| `161226.SZ` | 5 | 5 | 5 |
| `501018.SH` | 8 | 8 | 8 |
| `513100.SH` | 27 | 27 | 27 |
| `159915.SZ` | 0 | 0 | 0 |

因此导入器必须丢弃或明确标记零成交占位 K，不能只检查“每天 240 根”。否则回测会在停牌/未成交时用前收盘价虚构 09:50 信号和 10:00 成交。对于无成交标的，策略必须执行本方案第 7 节的“不可交易”规则。

### 2.2 搜索、证券属性与公司行动

`get_match_stkinfo` 已验证可以按代码或中文名称模糊搜索，并返回标准代码和名称。项目接口只保留 `.SH`、`.SZ`、`.BJ` 且属于允许品种集合的结果，避免把同名场外基金 `.OF`、期货或海外证券加入 CN 策略。

`get_more_info` 能返回 `HqDate`、涨跌停参考价和 `IsT0Fund` 等属性。目标池实测 `518880`、`501018`、`513100` 的 `IsT0Fund=1`，`161226`、`159915` 为 0。该字段可作初始值，但正式 instrument master 仍要用交易所产品清单交叉核验并允许人工纠正，不能只按“ETF/LOF”名称推断 T+0/T+1。

公司行动方面，目标池返回的送转/份额折算事件为：`518880` 1 条、`513100` 1 条、`159915` 1 条；`161226` 与 `501018` 当前为 0 条。原始四字段是每 10 份现金、配股价、每 10 份送转、每 10 份配售。事件必须连同 `Type` 和原始 payload 保存。TdxQuant 内置的前后复权可以做交叉对照，但正式回测仍用原始价 + 独立公司行动，且配股公式不能遗漏配股款。

### 2.3 当前仍未完成的验收

- 2026-08-23 是周日。已验证 HTTP 快照、批量最新价和 DLL `subscribe_hq` 均可调用，订阅后 5 个代码均收到一次通知；回调只含 `Code`，收到后还需再取 snapshot。周末返回的是 2026-08-21 缓存价，不能据此宣称交易时段实时性已通过。

## 3. 下一步仅需一次交易时段验收

5. 收盘后 `refresh_kline('1m')` 是否能读取当天 240 个标签，并与日线 OHLCV/Amount 核对。

## 4. 数据源职责与降级策略

### 4.1 主源：TdxQuant

建议职责：

- 沪深北股票、ETF、REITs、常用基金和指数代码表；
- 未复权日线和盘后分钟线；
- 最新价、昨收、开高低、累计成交量、盘口快照；
- 权息事件与 TdxQuant 前后复权结果；
- 已发生的交易日；
- 本地客户端可用时的行情总览批量刷新。

生产约束：

- 必须在 Windows 上启动并登录支持 TQ 的客户端；HTTP 当前只绑定 `127.0.0.1`，WSL 内的 Linux Python 不能直接访问 Windows 回环地址。
- HTTP 服务不需要 key，也没有独立鉴权。必须保持回环绑定，项目服务只暴露业务白名单，不能把任意 TQ method 透传给外部请求。
- `get_market_data` 单次最多 24,000 条，官方建议单次只传一个标的；历史任务应单标的、有限并发、按月或按季度分页。
- `fill_data` 固定为 `false`，不能用前值伪造停牌日或缺失分钟。
- 盘中 K 线限制与快照无时间戳决定了它不是严格实时分钟 K 源。
- 客户端升级可能改变 SDK/返回字段；启动时记录 TQ 版本，并执行契约探针。

### 4.2 备用：AKShare

按能力使用：

- 日线：`stock_zh_a_hist`（东财）或 `stock_zh_a_hist_tx`（腾讯）；
- 实时总览：`stock_zh_a_spot_em` 及沪、深、京分市场接口；
- 近期分钟：`stock_zh_a_hist_min_em` / `stock_zh_a_minute`；
- 公司行动：`stock_fhps_detail_em`；
- 历史交易日：`tool_trade_date_hist_sina`，仅作交叉核验。

限制：AKShare 是多网站适配库而非原始交易所数据服务，接口会随上游网页变化。东财 1 分钟历史明确只返回近 5 个交易日且不复权，交易日日历也不应作为未来调度的唯一依据。

### 4.3 BaoStock 的定位

保留为离线 QA/第三候选，不作为正式备用。原因是缺少足够的实时能力，北交所和长分钟覆盖仍需单独验证，并且其官网/API 文档近期改版，当前可运维性不如 AKShare。它可用于抽样对比沪深日线、复权因子和历史交易日。

### 4.4 交易日历的权威来源

已发生交易日可以由 TdxQuant `999999.SH` 日线生成；未来实时调度不能据此推断，因为本地日线只到最近已完成交易日。

建议把上交所年度休市安排作为 `CN` 未来日历主依据，并与深交所、北交所公告交叉核验。三所普通股票目前使用相同的周末/节假日休市框架，但仍保留 `exchange` 元数据，以便将来处理临时停市或规则分化。

## 5. 市场标签和标的模型

同意把用户可见且用于策略兼容校验的市场标签简化为一个枚举：

| 标签 | 含义与默认日历 |
| --- | --- |
| `US` | 美国股票/ETF，按美国交易所日历和纽约时区 |
| `CN` | 沪、深、北上市交易品种，按中国交易所日历和北京时间 |
| `CC` | 加密货币，7×24 |
| `FX` | 当前“特殊”中的美元指数、黄金等 24×5 序列 |
| `BD` | 美债收益率或债券序列；具体可交易/观测时段由标的属性给出 |

这 5 个值足以实现当前的策略隔离，不再设计三层“标签”。但交易引擎仍必须保存若干普通元数据；它们是执行参数，不是第二、第三套标签。例如同为 `CN`，上交所/深交所代码后缀、是否 T+0、每手数量、价格步长和涨跌停规则并不相同。

兼容规则保持简单且服务端强制执行：

- 候选、辅助标的和 benchmark 默认都必须与策略的 `market` 完全相同；
- `BTC/USD` 的原生标签为 `CC`，保留现有 `US <- BTC/USD` 单点例外，使用专门生成的美股会话日线；
- 不把这个例外推广到 `CN`，除非将来明确设计 BTC 的北京时间/A 股交易日派生序列；
- `518880`、`161226`、`501018`、`513100`、`159915` 虽然分别暴露黄金、白银、原油、纳指和创业板风险，但都在沪深交易所成交，所以全部标记为 `CN`。市场标签按交易场所/时钟定义，不按底层经济风险定义。

迁移时兼容旧值：读取 `US_EQUITY` 时映射为 `US`，新建策略只保存新枚举；历史运行快照保留原值和代码版本，避免修改既有审计结果。

instrument master 建议增加这些非标签字段：

- 稳定 `instrument_key`、`market`、`exchange`、`currency`、`timezone`；
- `instrument_type`（股票、ETF、LOF、REIT、指数等），只用于交易规则和展示；
- `valid_from` / `valid_to`、上市/退市日期和历史代码别名；
- `buy_lot_size`、`quantity_step`、`price_tick`、`same_day_turnaround`；
- `price_limit_profile`、`fee_profile`、停牌/可交易状态来源；
- TDX/AKShare 供应商代码、来源版本和人工覆盖状态。

北交所尤其不能只用代码做身份。存量股票在 2025 年全面切换为 920 号段，必须导入北交所官方新旧代码对照表。TdxQuant 已用新代码连续返回旧历史，但备用源可能仍使用旧代码。

## 6. 数据层设计

### 6.1 Provider 接口

新增统一接口，不让业务代码直接调用 TDX/AKShare：

```text
search_instruments(query, market='CN')
get_instrument(symbol)
fetch_daily(symbol, start, end, adjustment='raw')
fetch_minutes(symbol, start_at, end_at, period='1m')
fetch_quotes(symbols)
fetch_corporate_actions(symbol, start, end)
fetch_historical_sessions(start, end)
health()
```

实现：

- `TdxQuantHttpClient`：JSON-RPC、超时、错误码、重试、版本/延迟指标；
- `TdxQuantCnProvider`：字段、单位、代码、时区标准化；
- `AkshareCnProvider`：备用接口与能力声明；
- `MarketDataRouter`：按市场、数据类别、健康度和新鲜度路由；
- `CnRealtimeQuoteHub`：5 个策略标的的订阅心跳、事件窗口快照和时效审计。它提供点时 quote，不伪装成实时分钟 K。

### 6.2 入库口径

- 日线和分钟线统一入库 **不复权原始价**，`price_basis='raw'`。
- 公司行动单独存储；指标/图表按查询时点做复权，组合持仓由公司行动引擎处理。
- TDX `Amount` 为万元，内部统一乘 10,000 变成人民币元；实测 K 线 `Volume` 是最小成交单位，而 snapshot/`get_pricevol` 的 `Volume` 是手，后者对本目标池乘 100 后归一化为份。
- TDX 数值均为字符串，边界层完成 Decimal/缩放整数转换。
- TDX 分钟标签为结束时间，先减 1 分钟，再按 `Asia/Shanghai` 解释并存 `minute_utc`；保留 `provider_time_label` 以便审计。
- TDX 本地文件含零成交占位 K。canonical `minute_bars` 只保存实际成交 bar，零成交记录另计入 import quality manifest，不得作为信号或成交价。
- 每条/每批记录 `source_provider`、`source_version`、`fetched_at`、原始范围和质量状态。

现有项目已有 `data/market_data.sqlite`（标的、日线、公司行动、策略）和 `data/intraday_data.sqlite`（分钟、日历、导入状态）。现有 upsert 和后台任务可复用，但需要迁移：

- `symbols`、`intraday_instruments` 增加 `market`，现有记录回填 `US` 或 `CC`；
- `symbol_aliases` 扩成通用 provider alias，增加 `tdx_symbol`，不能继续只有 Yahoo/Twelve Data；
- `minute_bars` 增加来源/质量元数据；如保留成交额，还应增加 `amount_scaled`；
- `market_sessions` 不能继续只以 `trading_date` 为主键，至少改为 `(market, trading_date)`；
- 增加 session segment，避免把 A 股午休误当成可成交时间。

建议 segment：

```text
CN regular_1 09:30-11:30 Asia/Shanghai
CN regular_2 13:00-15:00 Asia/Shanghai
```

集合竞价单独标记，不与连续竞价分钟混为一谈。

### 6.3 搜索、更新与 SQLite 入库流程

可以实现用户提出的交互，而且与当前页面高度一致：

1. 用户输入代码或中文名；后端先查本地 instrument master，再调用 TDX `get_match_stkinfo` 补充结果。
2. 结果规范为 `518880.SH` 这类 canonical symbol，并仅展示沪深北允许品种；用户选择“包含分钟数据”。
3. 创建现有 `/api/market-data/update` 风格的后台任务，按 symbol 加锁，避免同一标的重复导入。
4. 调用 `refresh_kline(symbol, '1d')` 后单标的读取 raw 日线，验证字段、日期和 OHLC，再 upsert `daily_prices`；同步 `get_divid_factors` 与证券属性。
5. 若勾选分钟，调用 `refresh_kline(symbol, '1m')`，读取本地可得的完整窗口；完成结束标签转换、零成交清理和质量检查后，批量 upsert `minute_bars`。
6. 更新 sync state：实际最早/最晚分钟、总行数、零成交占位数量、最近完整交易日、源版本和质量结论；前端显示真实覆盖区间，不能写死“100 天”。
7. 入库后重读 SQLite 生成页面响应，策略、图表和回测不再直接依赖通达信文件。

初次分钟数据仍需要在客户端盘后下载一次；实测在完全没有 `.lc1` 时单独调用 `refresh_kline` 不会创建可读历史。首次存在后，程序可以自行刷新并读取。若某标的未初始化，页面应返回“请先在通达信盘后下载该标的 1 分钟线”的可操作状态，而不是保存空成功。

每日盘后同步只处理策略池、总览池和用户明确选择的标的，不默认下载 5,558 只分钟线。每次重读约 100 个自然日并 upsert；**绝不删除 SQLite 中更早的分钟**，这样从 2026-05-15 起会逐日形成永久自有历史。每日按实际成交分钟聚合，并与日线 OHLCV/Amount 做容差核对；午休不记缺口，停牌不前填。

全市场日线已在本地下载，可另设低优先级“导入全部本地 CN 日线”管理任务。官方建议 `get_market_data` 单次只传一个标的，因此应串行或很低并发运行，并允许断点续传，不能在普通页面请求里同步阻塞。

## 7. A 股交易日与回测语义

`CN` 固定为 `Asia/Shanghai`，没有夏令时。普通交易日核心时段为 09:30–11:30、13:00–15:00；开盘/收盘集合竞价需要独立事件语义。

现有代码中需要替换的美股假设包括：

- 只支持 `US_EQUITY` 的 market registry；迁移后兼容读取旧值、对外使用 `US/CN/CC/FX/BD`；
- 全局 XNYS/Alpaca calendar 和只有日期主键的 session 表；
- `09:30–16:00 America/New_York` 的规则校验、日志和事件排序；
- 把整段开收市之间所有分钟都视为连续交易的缺口检查；
- IEX 专用实时 hub；
- SPY/GLD benchmark、4.5% 无风险利率和固定年化交易日数；
- 每股固定佣金、允许杠杆/碎股、没有 T+1 与涨跌停的组合模型；
- 公司行动显示/复权只对 `asset_class='us_equity'` 生效。

### 7.1 订单与账户规则

不能只换日历，还应至少实现：

- A 股普通股票 T+1，当日买入股份不可当日卖出；
- 基金不能一概按 T+1。交易所允许部分债券、黄金、商品和跨境基金当日回转；应按 instrument 的 `same_day_turnaround` 执行。目标池的 TDX 属性也已经证明其值并不相同；
- 不同板块/品种的买入最小数量和数量步长，卖出零股规则；
- 按成交额计费、最低佣金、卖出印花税、过户费，并按生效日期版本化；
- 普通、ST、科创/创业板、北交所和上市初期的涨跌停 profile；
- 停牌、涨停买不到、跌停卖不出的保守成交规则；
- A 股 v1 强制 long-only、无碎股、总杠杆 1；融资融券另做市场能力；
- 价格 tick 与订单价格舍入；
- 现金分红、送转股、配股。配股是否参与需要显式策略/账户政策，不能自动假定。

现金红利税与持有期相关，若 v1 不实现，应明确输出“税前分红回测”而不是静默当作净现金。

### 7.2 事件语义

- `OPEN`：使用上一交易日已完成数据产生信号，以当日开盘可成交价模拟成交。
- `CLOSE`：只有收盘后才能确认完整收盘信号，沿用当前系统在下一交易日开盘执行的语义。
- `HH:MM`：只能落在连续竞价 segment 内；午休时间必须验证失败。
- 集合竞价事件如需支持，应新增 `OPEN_AUCTION_END` / `CLOSE_AUCTION_END`，不要借用普通分钟。
- 早退市、暂停上市、代码变更和历史 universe 要按 point-in-time instrument master 处理，避免幸存者偏差。

### 7.3 目标池的严格分钟回测

建立一个新的 CN 预置，而不是修改现有 US 预置的默认值：

```text
market = CN
symbols = 518880.SH, 161226.SZ, 501018.SH, 513100.SH, 159915.SZ
risk_check_time = 09:50
selection_time = 10:00
timezone = Asia/Shanghai
```

急跌和 WTME 公式可复用现有代码：历史完整日线提供预热；风险检查最后一段使用 09:50 前最后一根实际成交分钟的 close；WTME 当前观测使用 10:00 前最后一根实际成交分钟的 close，仍只以“前收盘—当前点时价”构造临时 OHLC，不读取当日最终高低收。

TDX 标签 `09:50` 表示 09:49:00–09:50:00 这一分钟，转换后正好是项目当前 `09:49` signal bar；标签 `10:01` 对应项目 `10:00` fill bar。不能把 TDX 标签 `10:00` 同时当成 10:00 成交价，否则会错一根。

零成交/停牌规则必须显式化：

- 导入时删除零成交占位 bar；事件前有实际成交、事件时无成交，则信号使用事件前最近实际成交，订单以事件后首根实际成交的 open 作为参考，并记录延迟分钟数；
- 当日事件前完全没有成交的标的，不参加 10:00 新买入排名；不能用前收盘占位价取得虚假低波动优势；
- 若不可交易标的是现有持仓，持仓锁定，不能虚构卖出。剩余现金是否买入其他标的由策略参数决定，默认不使用本应由锁定持仓释放的资金；
- 涨停无卖盘、跌停无买盘也不能只凭一根打印成交价假定足量成交。第一版至少用成交量、涨跌停价和盘口做保守判定，并输出“理论信号”和“可执行组合”两套结果；
- 回测数据 manifest 记录每次延迟成交、不可交易和排除原因，报表单列这些日期。

分钟覆盖从 2026-05-15 开始，但 WTME 40 日预热可以使用更早的日线，所以首日即可计算。70 个交易日足以验证工程正确性，不足以证明策略稳健；策略效果评估应继续积累数据，并报告急跌触发次数、换手、不可交易次数和交易成本敏感性。

### 7.4 只有日线时可以怎样准确降级

不能把“当天开盘价既作为决策输入、又作为同一个开盘价成交”称为准确回测：开盘价只有开盘形成后才知道，此时已经无法保证仍以同一价格成交。这会产生隐性未来信息和乐观成交。

长区间日线回测只允许两个明确改版，并与严格分钟结果分开命名、分开比较：

1. `previous_close_to_open`：以前一交易日收盘及更早数据做急跌/WTME 决策，下一交易日开盘成交。这是日线 OHLC 可以准确支持的推荐版本。
2. `open_signal_next_open`：使用当天开盘价构造信号，下一交易日开盘成交。它也无未来数据，但执行晚一天，已不是原策略。

若用户坚持用当天开盘价同时决策并成交，只能标记为 `proxy/optimistic`，不能满足“回测结果必须准确”的要求。当前已有 70 日分钟数据，因此目标池 POC 应优先跑严格模式，日线版本只用于更长区间的结构性对照。

### 7.5 指标和复权

TdxQuant 的 `front`/`back` 可用于供应商对照，但正式回测继续使用原始 K 线 + 独立公司行动：

- 指标历史按 as-of 日期做点时复权，避免未来公司行动泄漏；
- 组合估值和成交使用原始价；
- 除权日实际调整持仓股数和应收现金；
- 不直接使用 TDX 返回的 `ForwardFactor` 反推所有历史前复权价，官方说明它是区间沿用因子而非每天可直接乘用的准确前复权因子；
- 后复权结果依赖查询窗口，不能作为稳定入库序列。

## 8. 实时行情与决策

### 8.1 行情展示

优先调用 `get_pricevol` 批量刷新关注池，按需用 `get_market_snapshot` 补充盘口与日内字段。全市场一次约 2.7 秒，几十到上千只的总览性能充足。

每个 quote 必须附加项目侧 `fetched_at`，并通过以下条件标记新鲜度：

- 当前是否为 `CN` 交易 segment；
- 最新已完成日线日期是否等于预期；
- `LastClose` 是否与本地上一交易日收盘匹配；
- `get_more_info.HqDate` 是否为当前交易日；
- 连续采样时累计成交量是否单调；
- 订阅 callback 的最近接收时间、TDX 客户端/HTTP 健康状态和刷新错误。

周末测试已证明快照会返回最近交易日缓存价，没有 provider timestamp，因此界面必须显示“最近缓存价/采集时间”，不能笼统显示“实时”。

### 8.2 09:50/10:00 正式决策

这两个事件可以在不依赖盘中分钟 K 的前提下实现，因为急跌和 WTME 当前公式只读取一个点时价格。建议为 CN 增加独立的 `CnRealtimeQuoteHub`，不要把 TDX 硬塞进现有 `IEXMarketDataHub`：

1. 任务启动后订阅 5 个代码。官方示例说明 `subscribe_hq` 约每 6 秒回调、最多 100 只；本机已验证订阅/取消成功，但回调本身只有代码，因此 worker 收到 callback 后异步读取 snapshot。
2. 09:50 和 10:00 各建立一个短事件窗口：保存事件前最后一次合格 quote 作为 signal，再保存事件后第一次合格 quote 作为执行参考。两者都记录项目接收时间、请求耗时、callback age、`HqDate`、累计量和盘口。
3. 事件价格必须来自 TDX 主源；AKShare 可以并行交叉核对。主源无合格 quote、日期不符、回调超时或前收与数据库冲突时，正式事件失败关闭，不用备用源静默改排名。
4. 无当日成交或无可执行盘口的候选标为不可交易，执行第 7.3 节规则。特别是目标池中 513100 历史上多次 10:00 前无成交，不能把这种情况当成异常边角。
5. 保存可重放 event snapshot：所有 5 个标的都要写入，不只保存胜出者；邮件/页面同时展示理论评分、过滤原因、可交易状态和最终建议。

事件窗口的具体容忍值应由下一交易日 POC 决定，可先以 callback age 不超过 12 秒、事件前后各 10 秒为候选阈值。由于 TDX snapshot 没有交易所时间戳，最终能承诺的是“在事件时点附近采集的实时快照”；若验收目标要求精确到交易所标记的 09:49:59 收盘和 10:00:00 首笔，则必须换用带源时间戳的实时分钟/tick 数据源。

### 8.3 “实时分钟价格”的结论

- 当前价格：接口能力已确认，交易时段新鲜度待一次工作日验收；通过后可供 09:50/10:00 正式决策。
- 前几分钟的正式 1 分钟 OHLCV：TdxQuant 盘中不能由 `get_market_data` 取得。
- snapshot 中虽有 `Before5MinNow`，但没有明确 bar 时间戳和 OHLCV，不能当作完整 5 分钟 K。
- 项目可以从上线后持续采样 snapshot 构造 `observed_quote_bars`，供监控和故障诊断；它会漏掉采样间隔内的极值，不能与盘后官方 `.lc1` 混存，也不能替代严格历史回测数据。

AKShare 实时行情可以在主源中断时维持“降级展示”，但没有通过相同新鲜度验收前，不应自动替代正式交易决策。

## 9. 分阶段开发计划

### Phase 0：完成交易时段 POC

- 已完成：5 标的盘后分钟覆盖、标签、午休、每日日内根数、零成交占位、日线聚合、单位、搜索、公司行动、T+0 属性和订阅链路测试。
- 待完成：在一个真实交易日测 `get_pricevol`、snapshot、refresh、订阅 callback 的 p50/p95/p99、新鲜度、事件窗口和断线行为；收盘后确认当天分钟刷新。
- 非阻塞项：另选一个北交所代码下载分钟线，验证 `.BJ` 分钟覆盖。沪深目标池开发不必等待它。

退出条件：09:50/10:00 的 5 标的点时 quote 全部满足时效窗口；不满足则正式 CN 盘中任务保持关闭，只开放历史回测和展示。

### Phase 1：市场/标的基础模型

- 建立 market registry、instrument master、代码别名和兼容关系。
- 迁移 market session 为多市场 + 多 segment。
- 导入沪深北当前代码、ETF/REITs/指数以及北交所新旧代码映射。
- 后端和前端加入 `CN`，并把旧 `US_EQUITY` 兼容映射为 `US`；服务端强制校验所有候选、辅助标的、benchmark。

### Phase 2：数据适配和日线闭环

- 实现 TDX HTTP client、CN provider、健康检查和请求协调。
- 实现日线同步、公司行动、历史日历和官方未来休市表。
- 扩展复权服务支持 CN 资产；保留 raw storage。
- 行情详情、总览和指标改为根据标的 market profile 工作。

### Phase 3：目标池严格分钟回测

- 导入 5 个目标基金 70 日实际成交分钟，正确完成结束标签转换和零成交清理。
- 创建 `CN + 09:50/10:00 + 5 标的` 的急跌/WTME 预置，保留 US 预置默认时间。
- 实现不可交易/延迟成交、T+0/T+1、100 份步长、费用、涨跌停和锁定持仓。
- 跑数据 manifest、逐事件审计和手工金标准用例，先验证正确性，再讨论收益表现。

### Phase 4：CN 通用回测与长区间日线变体

- 扩展其他沪深常见股票/ETF、日频 OPEN/CLOSE 模式和明确命名的日线策略变体。
- 完成公司行动、税费、各板块涨跌停、上市初期、退市和历史 universe 的通用处理。
- 北交所分钟通过 Phase 0 额外验收后再打开 BSE 分钟能力标志。

### Phase 5：实时展示和实时决策

- 总览批量最新价、单标的快照、陈旧/降级状态。
- CN scheduler、quote hub、断线恢复、主备交叉核验和失败关闭。
- Phase 0 通过后，只先开放 5 标的 09:50/10:00 点时任务；这不等于开放任意策略的官方实时分钟 K。
- 至少连续观察 10 个交易日，覆盖开盘、午休、收盘、节前和公司行动日。

## 10. 验收清单

- 沪深北普通股票覆盖；ETF/REITs/常用指数另列覆盖率。
- 同一标的主备日线 OHLC、成交量、金额误差在约定阈值内。
- 交易日历覆盖历史区间和未来至少 1 年，节假日与三所公告一致。
- 原始/前复权/后复权和公司行动组合处理通过已知案例。
- 分钟数据没有午休伪缺口、没有前填停牌数据、时间标签无一根偏移。
- 零成交占位 K 不参与信号/成交；513100 等 10:00 前无成交案例不会产生虚假买卖。
- 正式决策所用 quote/bar 有采集时间、来源、质量状态和可重放 manifest。
- 09:50/10:00 交易时段实测满足已约定 callback age 和事件窗口；未满足时事件失败关闭。
- TDX 关闭、登出、HTTP 超时、返回缓存价、AKShare 限流时均有可解释降级。
- 回测无幸存者偏差声明；若只支持用户显式选择的当前标的，界面明确限制。
- 数据许可允许当前使用场景；若用于商业服务或再分发，单独确认通达信及上游网站授权。
