# 七星 ETF 轮动策略实现与使用说明

## 1. 实现范围

“七星 ETF 轮动”已经作为 `sevenstar_etf_rotation` v1.1.0 内置代码策略实现。前端不能
新建代码策略，但会自动出现两个可编辑预置：

- 小池：GLD、USO、SPY、QQQ、DIA、IWM、TLT；
- 大池：41 个候选，覆盖商品、美国指数/风格、行业、国际、主题、债券和 BTC/USD；
- 防御标的默认为 BIL，不参与趋势排名，也不进入 `auto` 基准。

原聚宽文件的执行逻辑已经转入 `services/backtest/code_strategies.py`。项目不依赖聚宽
API，也不保留运行时脚本加载机制。

应用首次启动还会幂等创建一个停止状态、关闭邮件并跟随源策略的“小池”实时决策任务；
大池不会重复创建实时任务。小池与大池使用完全相同的策略类、v1.1.0 代码和默认参数，
差异仅是候选池与描述。用户软删除该内置实时任务后，后续启动不会让它复活。

实时任务详情默认以行情总览中的全部标的作为观察范围，展示是否过滤、长期年化趋势、
R²、短动量、启用时的量比、最终评分、面板排名和目标。标的名前蓝点表示属于正式小池；
观察面板只读内部数据库，不会扩充正式候选池。正式定时决策仍在事件时点独立请求 IEX，
并只按任务/run 快照中的候选池计算和发送邮件。

## 3. 核心算法

排名事件默认在 14:00 ET。每个候选使用此前 25 个完整交易日收盘价和事件前最后一根
完整分钟的收盘价，共 26 个点：

```text
y = log(price)
x = 0..N
w = 1..2 线性递增
q = w²
weighted_mean = Σ(q * y) / Σq
centered_y = y - weighted_mean
slope, centered_intercept = polyfit(x, centered_y, degree=1, w=w)
fitted_centered = slope * x + centered_intercept
ss_res = Σ[q * (centered_y - fitted_centered)^2]
ss_tot = Σ(q * centered_y²)
raw_r_squared = 1 - ss_res / ss_tot
r_squared = clip(raw_r_squared, 0, 1)  # 仅吸收机器精度误差
annualized = expm1(slope * 250)
score = annualized * r_squared
```

`np.polyfit(..., w=w)` 把 `w` 施加在未平方的残差上，因此回归的有效残差重要性是
`q=w²`。默认的“一致加权 R²”模式使残差平方和、总平方和及加权中心都使用同一个 `q`，避免回归与
R² 口径不一致。先中心化再拟合只改善数值稳定性，不改变 WLS 斜率。对恒价或加权对数
方差已低于浮点精度的近恒价序列，直接返回零年化、零 R² 和零评分；若原始 R² 超出
允许的机器误差带，该观察也以零 R²、零评分关闭。对外输出的 R² 始终位于 `[0, 1]`。

年化趋势使用数值更稳定的 `expm1(slope * 250)`。若极端正斜率使指数超出浮点上限，
年化值有限饱和为最大可表示浮点数，所得评分继续接受最高评分阈值检查，不让单个极端
候选因溢出中断整次回测。第一阶段修复仍保留指数年化及
`score = annualized * r_squared` 的排名语义；
取消指数年化属于后续模型变更，不包含在当前版本中。

`score` 必须严格满足 `min_score < score < max_score`。在一致模式下，拟合年化趋势还必须
严格为正；这是过滤代码为 `non_positive_trend` 的独立符号保护，可阻断“负收益乘负 R²”路径。
同分时不按代码二次排序，而是保持候选池顺序。

v1.1.0 增加“历史 v1.0.0 不一致权重”兼容模式，用于复现和对照旧结果：

```text
slope, intercept = polyfit(x, y, degree=1, w=w)  # 拟合有效重要性为 w²
ss_res = Σ[w * (y - fitted)²]
ss_tot = Σ[w * (y - mean(y))²]                   # 普通均值
r_squared = 1 - ss_res / ss_tot                  # 不截断
annualized = exp(slope * 250) - 1
score = annualized * r_squared
```

该模式故意恢复回归与 R² 权重不一致、普通均值、可为负的 R²，并停用
`non_positive_trend`，因此能够再次出现“负收益 × 负 R² = 正评分”。它只增加有限值和
溢出保护，不修正旧公式本身。默认值仍是数学一致模式，选择历史模式属于用户明确接受
上述风险的兼容行为。

过滤顺序与边界：

1. 高点回撤保护：当前价小于等于此前 N 日最高价乘以 `(1-阈值)` 时排除；它与持仓
   成本无关，因此界面称为“高点回撤保护”而不是盈利止盈。
2. 放量过热：当日 09:30 至排名信号分钟的累计量/此前 N 个完整日均量严格大于倍数，
   且拟合年化收益严格大于年化门槛时排除。
3. 短期动量：当前价相对 N 日前收盘价的简单收益按 250/N 年化，严格低于下限时排除。
4. 近三段单日急跌：当前事件价/昨日收盘、昨日/前日、前日/再前日任一严格低于
   `1-急跌阈值` 时排除。
5. 非正长期趋势：一致模式下，拟合年化趋势小于等于零时排除，日志原因为“长期拟合趋势非正”；历史兼容模式不执行此项。
6. 评分开区间：`score` 不严格位于用户设定的最低与最高评分之间时排除。

溢价率过滤未实现：原策略只用它排除过大溢价，美股 ETF 通常较小，且当前数据源没有
可审计的历史 NAV。系统不会用缺失值猜测溢价，也不会因此拒绝候选。

## 4. 日内事件与真实成交顺序

默认事件顺序：

1. 11:00：独立检查所有候选持仓和 BIL 的高点回撤，触发后按 11:00 分钟开盘价卖出；
2. 14:00：用 13:59 完整分钟收盘价计算一次排名并缓存；先按 14:00 分钟开盘价卖出
   不在原始前 N 名目标中的持仓；
3. 14:01：复用 14:00 缓存，不重新排名；以 14:00 完整分钟收盘价再次检查高点回撤，
   再按 14:01 分钟开盘价成交；
4. 若仍有非目标持仓未卖出，本次不买；没有合格候选时转入 BIL，BIL 不可用时持有现金；
5. N 个目标按账户总权益等权。金额偏差严格超过容差才再平衡，空仓目标始终允许买入。

同一事件由引擎统一先卖后买，手续费沿用项目的“每股手续费与每单最低手续费取较大值”，
不改成成交额比例。最小交易额只跳过加仓和部分减仓，完整清仓永远允许。美股 ETF 默认
整数股；BTC/USD 固定按 0.0001 BTC 步长。

提前收市日，默认 14:00/14:01 自动映射为正式收市前第 2/第 1 分钟，即 13:00 收市日
在 12:58/12:59 分钟开盘成交。高点回撤检查不得晚于 12:55。其他无法映射且超出实际
时段的事件继续 fail-closed。

## 6. 数据完整性和晚成立标的

主库 `symbols` 保存 `asset_class`、`quantity_step`、`history_start_date`、来源和核验标记。
每次分钟或日线导入都更新“供应商实际返回的最早日期”，只允许向更早日期修正。MAGS
实测最早为 2023-04-11；Alpaca BTC/USD 分钟数据实测从 2021-01-01 起提供。

候选不会因为晚成立而让整个 2020 起始回测失败。系统先严格检查其实际有数据后的每个
NYSE 交易日是否连续、完整和合法；达到自身最长参数预热长度的首日才动态加入排名。
在此之前，策略和 `auto` 基准都不能读取或交易它。`auto` 基准的每个候选固定占
`100/池大小` 的目标槽位，未具备资格的槽位保留现金，首次具备资格的交易日开盘买入，
不把其额度临时分给其他标的。

BTC 原始分钟线保持 7×24 存储，策略日线只聚合真实 NYSE 交易日的 09:30–16:00 ET，
周末和美股休市日不进入趋势回看；策略也只在美股事件时钟交易 BTC。BTC 没有股票公司
行动。股票/ETF 仍严格核验拆股和分红。

完整分钟数据可断点导入：

```bash
# 冒烟：每个标的一页，保留续传 token
python -m scripts.bootstrap_sevenstar_data --pool large --max-pages 1

# 从断点继续，直到当前延迟行情结束
python -m scripts.bootstrap_sevenstar_data --pool large

# 只处理指定标的
python -m scripts.bootstrap_sevenstar_data --symbols MAGS BTC/USD
```

完整任务结束后才派生日线并运行质量报告。候选池和显式基准属于必需数据；发现问题时
预检立即报告第一个出错标的和日期，例如“标的 DIA 缺少 2024-01-03 的日线行情”，便于
直接补齐对应数据。任何日线缺口、不完整日线、非法 OHLCV、事件两侧分钟缺失、未结束
交易日、日历或公司行动无法核验都会停止回测，不会自动填价。

防御标的 BIL 是可选的辅助标的，不是候选池成员。BIL 完全没有本地日线时不会再触发
“部分标的没有本地日线行情”；其可用日期记为 `None`，策略在本应转入 BIL 的时点持有
现金。若 BIL 已有一段本地历史，则其历史起点之后仍执行与候选池相同的严格连续性和
分钟事件校验，避免用有缺口的数据产生虚假成交。

## 7. 基准

- `none`：无基准；
- `SPY` / `GLD`：首次具备资格的交易日开盘买入并持有；
- `auto`：候选池全部标的等权买入并持有，使用上节的晚成立现金槽位规则。

基准使用与策略相同的初始资金、数量步长、每股/最低手续费、滑点、拆股和分红。防御 BIL
不进入 `auto`。

## 8. 验证

每天 14:00 排名时，每个当日已具备数据资格的候选都会写入一条 DEBUG 日志，事件类型为
`SEVENSTAR_DAILY_SCORE`。日志同时记录 `trend_formula_mode` 和原始评分；若候选被高点回撤、放量过热、短期
动量、近三段单日急跌、非正长期趋势或评分开区间规则排除，同时记录所有命中的代码和中文原因。

回测页可下载 XLS：第一个工作表为逐笔买卖，第二个工作表按“每天一行、每个候选评分
一列”输出，明确列出趋势公式，并分别汇总六类硬过滤标的、合格排名、最终目标、操作/点位/标的及卖出
PnL。这样可直接用于 Excel、Python 或其他统计工具做横截面和时序分析。

```bash
python -m unittest tests.test_sevenstar_strategy -v
python -m unittest discover -s tests -v
```

专用测试分别复算一致 `q=w²` 与历史混合权重公式，并检查恒价/近恒价、R² 范围、评分符号、
价格尺度不变性、极端年化有限性、池内容、参数交叉约束、晚成立动态资格、
提前收市映射，以及两日换仓中 14:00 先卖、14:01 后买和下一分钟开盘成交。通用测试继续
覆盖 Decimal 资金恒等式、FIFO 含费盈亏、手续费、滑点、指标、公司行动、API 和数据库
迁移。真实 Alpaca 冒烟导入用于验证 MAGS/BTC 两套端点、分页续传、历史起点和 BTC
0.0001 精度；收益表现不属于通过标准。
