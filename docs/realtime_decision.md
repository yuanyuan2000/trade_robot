# 实时决策模块

本模块由两条用途严格隔离的链路组成：“行情总览标的实时观察面板”和“任务候选池正式
事件/邮件”。两者使用同一个策略定义，但观察面板是在最新数据库行情上模拟当前时点，
正式链路只在预定事件上执行；标的集合、输入快照、排名范围、目标含义与行情来源均可不同。
模块只提供交易辅助信息，不自动下单。

## 两条数据链路

| 项目 | 实时观察面板 | 正式决策与邮件 |
| --- | --- | --- |
| 标的集合 | `symbols.show_in_overview=1` 的全部标的 | 任务/run 策略快照中的候选池及必要辅助标的 |
| 当前价格 | 行情总览内部 SQLite 数据 | 事件时点独立请求 Alpaca：股票走 IEX，BTC/USD 走 Crypto |
| 更新方式 | 面板可见时每 60 秒轮询内部 API | 只在 OPEN、CLOSE 或指定 `HH:MM` 事件执行 |
| 计算语义 | 按策略定义模拟以最新数据立即观察 | 按策略事件时钟进行正式决策 |
| 排名与目标 | 仅用于观察，并标记为“面板排名/面板目标” | 写入决策、邮件、目标建议状态和审计日志 |
| 外部 API | 禁止 | 允许且不受行情总览自动更新开关影响 |

面板不会把行情总览标的注入任务候选池，正式决策也不会使用面板排名。标的名前的蓝色小点
只表示它属于有效候选池；运行中读取 run 不可变快照，停止时读取任务快照。行情总览更新
与正式事件当前可以分别来自 SIP、IEX 和 Alpaca Crypto；系统保留来源信息，不把不同 feed
伪装成同一来源。

## 阶段一：数据与一致性

- 实时任务创建时复制历史回测策略的完整快照；任务可选择持续跟随策略 revision。
- 任务启动时再次同步跟随策略；运行中的每个 run 使用不可变快照。若源策略 revision 或代码实现
  版本在任务运行期间变化，调度器会在下一个事件边界结束旧 run、创建新 run，并保留上次
  目标建议、待下一开盘生效的指令及兼容的策略运行状态；已从新策略范围移除但仍有目标的
  标的会生成明确的 0% 退出建议。未开启跟随的任务继续固定使用
  自己的快照。
- 历史回测与跟随型实时任务通过同一个“运行时策略快照”入口解析代码策略：统一采用当前代码
  版本、同一套参数校验，并自动补齐代码策略新增参数的默认值。源策略默认运行设置发生变化时，
  跟随任务同步全部共用设置，不保留任务级设置覆盖。
- 代码策略运行状态只恢复当前实现仍声明的字段，且永远不恢复 `params`；参数始终来自当前 run
  的已校验策略快照。因此代码策略增删参数或内部状态字段时，旧事件状态不能反向覆盖新实现。
- 决策沿用 `BacktestEngine` 的事件、表达式和代码策略计算入口。代码策略通过可选的
  `observation_columns()`、`observe_latest()`、`observation_target_count()`、
  `observation_target_weight()`、`observation_strategy_leverage_multiplier()` 和
  `observation_buy_event()` 明确拥有自己的
  最新行情观察接口；没有实现该接口的策略在面板中显示不可计算。面板服务只构造数据库上下文、
  调用策略并渲染结果，不硬编码某个策略的中间指标。非代码策略仍使用同一 DSL 表达式。
- 每个事件保存行情来源、feed、信号时间、下一开盘参考价、数据清单、策略日志和目标建议状态。
- 目标建议状态只保存各标的策略目标百分比、应用杠杆后的目标敞口百分比，以及“动态/手工
  配置层”和“策略附加层叠加后的最终单标的杠杆”。它不保存初始资金、现金、股数、成本、
  手续费、滑点、盈亏、分红应收或真实账户持仓。旧版本只保存
  最终杠杆的状态会在首次恢复时按配置层兼容迁移，避免把旧动态杠杆与当前手工输入相除后
  错误推导出小于 1 倍的策略倍率；早期 v2 虽已有最终杠杆字段但配置层为空的状态也按同一
  规则迁移。若旧错误已把倍率反复相乘到 100 倍以上，恢复时会把无法拆分的旧乘积重置为
  1～10 倍范围内的配置层，再由当前策略重新计算，而不是先把异常乘积交给组合校验。
  下一次成功事件会自动写回完整新格式。决策恢复因此不会再在生成邮件前触发
  “运行中的单标的杠杆率必须在 1 至 100 之间”。
- 状态还保存待下一开盘生效的 `CLOSE` 指令。收盘信号与历史回测使用同一时间边界，不会把
  同一收盘价当作可执行结果，而是在下一交易日 `OPEN` 取得开盘参考价后更新模型目标；即使
  策略本身没有开盘规则，调度器也会增加这个边界事件。实时决策不模拟真实账户的拆股、现金
  分红、费用或结算，用户需在收到建议后结合自己的券商账户处理。
- VOLAT 动态单标的杠杆仍会在每个正式事件更新；运行设置“动态杠杆变化时自动再平衡”开启
  时，倍率变化会按最近策略目标刷新模型目标敞口，关闭时则只把新倍率用于策略后续主动建议。
  换标、规则命中和代码策略自身调仓不受该开关抑制。实时任务停止时也可在“策略参数”中
  单独修改该开关；运行中的任务继续使用不可变 run 快照。
- 历史回测策略携带同一份市场契约。当前仅支持美股：`XNYS` 日历、
  `America/New_York` 时区；面板和正式决策都先过滤非美股交易日，具体决策时间按美东时间解释。
- BTC/USD 在美股策略中读取独立的 `US_EQUITY_SESSION` 日线，而不是行情页的 24/7 原生日线。
  面板与正式决策因此使用相同的已完成会话历史；面板仍可叠加“当前时点”暂定观测。
- 任务启动和每次正式事件都根据策略公式/代码策略的实际最小回看长度，取得事件日前精确的
  已完成美股交易日集合，并逐标的检查缺日和 `is_complete`。检查范围来自 run 的候选池和
  代码策略辅助标的，与 `show_in_overview` 无关；缺口会从最早日期开始补数并再次校验。
- 事件计算使用校验完成后冻结的同一份历史快照。来源、周期、价格口径、历史截止日、更新时间
  和数据指纹写入 `DATA_HISTORY_AUDIT`，正式事件信号价与时间写入 `DATA_EVENT_SNAPSHOT`。这些
  明细保留在事件 calculation 日志中，不额外扩充邮件正文。

## 行情更新与调度

- 股票免费数据使用 `feed=iex`，BTC/USD 使用 Alpaca Crypto `location=us`。分钟事件取上一根
  完整分钟收盘作为信号价，当前分钟开盘仅作为人工执行参考。事件前最新完整分钟若已滞后
  超过 5 分钟，视为行情不完整并停止本次决策。
- `OPEN` 使用上一交易日完整会话收盘（BTC 也读取 `US_EQUITY_SESSION` 上一行），绝不使用未来数据；
  `CLOSE` 使用实际会话收市前最后一根完整分钟/完整股票日线且不伪造成交价。
- 交易日历按美东时区处理，支持开盘、收盘、`HH:MM`、夏令时和提前收市；超过 60 秒无法
  取得数据时跳过并记录原因。
- `IEXMarketDataHub` 这个兼容类名不再代表仅支持股票，也不运行 15 秒最新价轮询。每个正式
  事件现场按标的资产类型取得可审计快照，事件以外不请求事件行情。
- `MarketOverviewRefreshCoordinator` 是唯一的行情总览后台更新所有者：启动时更新一次，
  自动开关开启后每 5 分钟更新一次。开关保存在 `system_settings`，行情页和实时决策页显示
  并修改同一个值；任一页面切换后会通过页面内状态事件立即同步另一个开关。关闭它不会
  禁止正式事件取数。
- 行情总览每轮只校验 `show_in_overview=1` 的标的：最近 260 个已完成交易日存在缺口时才
  补历史；交易时段另写入 IEX 当天暂定日线，非 Alpaca 路由保留近期刷新。它不再自动维护
  分钟历史。单标的手动更新先刷新近期窗口，再采用“检查—按缺口补数—复核”规则；只有
  明确勾选时才下载分钟数据。
- 进程级数据请求协调器对同一标的、同一起点的在途日线补数去重。正式决策优先级最高，手动
  更新和低优先级行情总览合计最多占一个执行槽位，因此分钟导入、启动或五分钟刷新不会独占
  数据通道；不同标的仍受供应商全局限流器约束。
- competition 正式决策要求全部候选标的和所有辅助标的取得有效历史与事件快照；缺少任意
  一个就失败关闭，避免以缩小后的候选池产生不可比排名。BTC/USD 与股票执行同样的候选池
  完整性规则，只是日线序列和事件 API 按资产类型路由。

所有运行任务由一个可唤醒的中央调度线程维护。普通等待只计算并保存最近事件时间，不占用
`REALTIME_MAX_WORKERS` 事件线程，也不获取标的行情；最多每 30 秒进行一次状态兜底检查。
只有关键事件到点时才向线程池提交一次行情获取与决策计算，因此线程上限约束的是“同时发生
的关键事件”，而不是可运行任务总数。

普通等待状态点击终止会立即清除下次触发并结束运行记录。若关键事件已经开始获取行情、执行
策略或提交邮件，任务转为“终止中”，允许本次事件完整落库并提交通知，完成后自动停止；从
点击终止起不再调度后续事件。尚在线程池排队、但还未开始处理的事件可以直接取消。

## 实时数据面板

进入任务详情后默认显示面板，右上角图标分别切换面板、策略参数、通知设置、决策与邮件
日志。页面同一时刻只展示一块内容。

任务总览在桌面端采用四列紧凑卡片。竞争策略卡片复用下述面板计算结果，显示行情总览范围
内评分最高的三个合格标的，并按金、银、铜区分；不足三个时按实际数量显示，非竞争策略
不显示推荐。该推荐只用于总览观察，不改变正式任务候选池或邮件目标。

所有面板固定包含标的、最新价格、目标敞口、更新时间、状态/原因、面板排名与面板目标，并支持
搜索、候选池筛选、状态筛选、任意列升降序、固定表头和行级计算明细。动态指标列如下：
状态单元格只常驻显示“通过”“已过滤”等简短状态，具体原因移到状态标签的鼠标悬停
提示中，避免原因小字持续占用行高。

“目标敞口”不是当前账户已经持有的仓位，而是该标的若此刻被选中时的模型敞口比例。它对行情
总览中的每个标的计算，不限于第一名或当前面板目标；公式为策略目标权重 × 整体杠杆 ×
单标的杠杆 × 策略附加杠杆。运行中的任务读取不可变 run 快照，停止的任务读取任务快照；
启用动态杠杆时按当前观察价计算 VOLAT 和单标的杠杆。因此实际入选行与同口径正式决策邮件
中的目标敞口一致，数据不足以计算动态杠杆时显示“—”。

面板含义是：按任务当前有效策略快照，把内部数据库最新行情当成“现在”，模拟策略此刻会
计算出的中间量、过滤和排名。它不是最近一次正式决策，也不会展示最近正式决策值；策略
可以使用完整历史日线、当前价格或自建的暂定观测，所以 WTME/ATR 等列与行情页采用
标准 K 线定义的指标不必相等。页面以小字和帮助提示持续说明这一差异。

面板顶部不再占用独立统计卡片；计算时间以及总览、候选池、通过、已过滤和不可计算数量
合并为工具栏下方的一行辅助信息，以便首屏容纳更多数据行。

- 七星：长期年化趋势、R²、短期年化动量、量比（启用时）和最终评分；
- 急跌/ATR：N 日价格位移、ATR 和 ATR 评分；
- 急跌/WTME：加权收益 `Rw`、加权标准化真实波幅 `Aw` 和 WTME 评分；
- 非代码：由任务自己的受限面板脚本定义。

每个指标列的悬停说明按任务当前生效参数展示回看天数、计算口径、用途和关键过滤阈值。非关键的逐日急跌明细、代入公式和输入值放在行级“查看”中，
避免表格过宽。面板展示层会去掉动态列名开头重复的“策略”，所有数值最多显示四位有效数字。
数据不足或单标的公式失败只影响该行，状态显示“不可计算”。

“重新计算”及 60 秒自动轮询都调用 `GET /api/realtime/tasks/<id>/dashboard`，只读取主库；
响应明确返回 `source=market_overview_database` 和 `external_api_called=false`。结果有短时内存
缓存，价格更新时间、任务 revision、面板 revision 或策略 revision 变化时自动失效；另有
`observation_mode=strategy_latest_simulation`、`formal_decision=false` 供客户端与审计明确区分。

## 非代码面板脚本

创建非代码实时任务时自动生成可编辑的受限 JSON。它不是 Python/JavaScript，不支持导入、
网络、文件或任意代码执行，只允许现有 DSL 的 `price`、`position`、OHLCV、MA、EMA、ATR、
算术、比较和布尔运算。最多 12 个动态列。例如：

```json
{
  "version": 1,
  "columns": [
    {
      "key": "score",
      "label": "评分",
      "expression": "(price - close(5)) / atr(5)",
      "format": "number",
      "help": "用于当前面板标的之间排序的策略评分。",
      "event": "OPEN"
    }
  ],
  "default_sort": {"key": "score", "direction": "desc"}
}
```

脚本根据策略规则和 competition 配置自动提取指标，兼容 single、distribution、competition、
单标的、无过滤及无评分场景。它使用独立的 `panel_revision`，因此运行中也可校验和保存；
修改只影响展示列，不修改策略快照、正式规则、邮件和目标建议状态。“恢复自动生成”会明确覆盖
自定义脚本。

## 策略参数与运行设置

实时任务的“策略参数”默认使用可视化表单，不要求手写 JSON：

- 代码策略根据与历史回测共用的参数目录生成控件，因此参数类型、选项、范围和后端校验一致；
- 非代码策略可编辑候选标的、单标的上限/杠杆、动态杠杆开关、规则以及 competition 选标；
  single、distribution、competition 三种模式都保留原定义自由度；
- “高级 JSON”仍可编辑完整 `definition`，修改后会回填可视化表单，作为复杂配置和旧数据的
  兼容入口；
- 跟随源策略时策略定义只读，源 revision 在事件边界同步；取消跟随后保存独立快照。

设置按领域隔离。实时任务只接受 `leverage_multiplier` 和 `dynamic_leverage`，因为它们会改变
目标敞口。初始资金、比较基准、每股/最低手续费、滑点、是否允许碎股、无风险利率和回测
日志开关只用于历史模拟，不出现在实时编辑器，也不会写入新任务或 run 的实时设置快照。
历史回测界面把这些控件分为“回测区间与分析”“目标仓位与风险”“历史成交模拟”三组，
共享控件只复用共同语义，不用一个巨型设置对象强行覆盖两类场景。

取消跟随后，任务可在 `settings_overrides_json` 保存相对自身策略快照默认值的稀疏覆盖。
勾选跟随后会立即清空这些覆盖，策略定义、整体杠杆和全部动态杠杆设置均回填并锁定为源策略
当前值；停止任务详情加载、任务启动和运行事件边界还会再次校正。旧数据库会自动增加该列。

## 任务与 API

- 总览页“实时决策”卡片支持创建、启动、终止、删除和进入详情。
- 点击“运行”时先校验代码策略版本；系统没有保存旧版本实现，因此版本不一致时会在历史
  数据检查和创建 run 之前直接拒绝启动，并要求先重新保存源策略参数后再运行。
- 跟随策略或运行中时正式策略定义锁定；独立面板脚本仍可编辑。
- API 除任务 CRUD、`/start`、`/stop`、`/events` 外，还包括 `/dashboard`、`/panel`、
  `/panel/validate`、`/panel/regenerate` 和支持 `all/decision/mail` 筛选的 `/logs`。
- 删除是软删除；被实时任务引用的历史策略不能删除，避免破坏审计。

首次启动会幂等创建一个“七星ETF轮动实时决策（小池）”：默认停止、邮件关闭、跟随源
策略。七星小池与大池预置已确认使用同一 `SevenStarEtfRotationStrategy`、代码版本和默认
参数，只是候选池与描述不同。种子状态记录在 `realtime_task_seed_state`；软删除后不会复活。

## 阶段四：邮件与审计

- QQ SMTP 默认 `smtp.qq.com:465` SSL；Gmail SMTP 默认 `smtp.gmail.com:465` SSL，也支持 STARTTLS 配置。
- 邮件通道是发件身份（服务器、账号和授权码），收件邮箱是通知目标；两者填写同一个地址是合法的“自发自收”，不会重复发送。
- `.env` 中的 `QQ_ADDRESS`、`QQ_AUTHORIZATION_CODE` 仅在启动时加密写入本地通道，接口永不返回明文或密文。
- 密钥由 `REALTIME_MASTER_KEY` 或 `data/.realtime-master.key` 保护，文件权限为 600；生产环境应设置稳定的 `REALTIME_MASTER_KEY`。
- 普通事件发送由数据库原子限频，单任务至少间隔 60 秒；网络/临时失败最多按 10/30/120 秒重试，重试不占用新的普通发送额度。
- 可用逗号选择只接收指定事件（如 `OPEN,CLOSE,10:00`），也可只在目标建议发生变化时通知。
  可选发送时刻按美东时间解释：事件发生在该时刻前则排队至当天发送，事件发生在该时刻后
  则排队至下一天；不填写时在事件完成后立即进入发送队列。
- “按当前行情发送测试决策邮件”不是固定文案的 SMTP 探针。它直接复用数据面板的
  `market_overview` 与本地日线数据库口径构造统一快照，不会为测试额外请求 Alpaca、Yahoo
  等外部价格 API，也不会自动更新数据库。它保留各事件的逻辑名称并按正常顺序逐项调用
  同一回测/实时策略引擎；WTME 因而会先
  演练风险检查、再让轮动决策继承该内存测试状态，共发送两封邮件。视觉/代码策略以及
  single、competition、distribution 均由同一事件枚举和求值入口处理；跟随型停止任务先
  同步源策略，运行中任务则使用当前不可变 run 快照。
- 测试遵守邮件设置中选择的事件范围，但主动绕过启用开关、“仅目标变化”、普通发送限频和
  固定发送时刻，并直接发送给临时输入的测试收件人。每封主题在渲染后的原标题末尾追加
  “（测试）”。测试状态仅在内存中推进，不新增或更新正式 run、决策事件、通知日志和目标
  组合，也不会触发正式决策所使用的历史修复回调。数据面板缺少候选或辅助标的本地行情时
  明确失败，由用户先通过正常行情更新功能刷新数据。
- 通知、每次尝试、SMTP 错误、发送时间和完整正文均写入日志。代码策略邮件只保留前 12 条评分摘要，详细公式仍在事件 calculation 日志中。
- 急跌/ATR 与急跌/WTME 策略都按事件区分内容：风险检查邮件列出过滤结果与模型目标调整；
  ATR 轮动邮件保留评分、排名和调仓建议，WTME 轮动邮件按“标的、模型目标敞口、WTME评分、
  急跌过滤后排名”排列，计算公式仍只保存在事件 calculation 日志中。目标敞口是策略目标
  应用整体、动态/手工单标的及策略特殊杠杆后的模型比例，不代表券商账户中的实际持仓。
- 每封默认正文还列出完整目标组合及相对上次建议的进入、退出、调整或不变，并明确提示系统
  未连接交易账户、不计算股数、费用或盈亏。
- 邮件以 multipart 同时提供纯文本和 HTML；HTML 表格固定列布局、单元格允许自动换行，
  `BTC/USD` 等较长名称不会再挤出列边界。
- 非代码策略模板是简单的纯文本替换，不是表达式语言。双大括号内只能使用系统定义的完整
  名称，不能填写自定义字符串、数字或公式；固定内容直接写在占位符外。可用占位符为：

  | 占位符 | 替换内容 |
  | --- | --- |
  | `{{task.name}}` | 任务名称 |
  | `{{decision.date}}` | 决策日期，如 `2026-08-05` |
  | `{{decision.time}}` | 规则时点原值，如 `OPEN`、`09:45` |
  | `{{decision.time_label}}` | 带美东时间说明的决策时点 |
  | `{{decision.datetime}}` | 决策日期与规则时点 |
  | `{{message.generated_at}}` | 邮件正文生成时间；不是 SMTP 实际送达时间 |
  | `{{decision.actions}}` | 一行或多行动作、标的、目标仓位及目标敞口 |
  | `{{decision.basis}}` | 命中规则、条件公式和本次指标实际值 |
  | `{{decision.summary}}` | 完整默认正文 |

  例如 SPY 8/13 EMA 策略可填写：

  ```text
  决策时点：{{decision.time_label}}
  邮件生成：{{message.generated_at}}
  决策内容：
  {{decision.actions}}
  决策依据：
  {{decision.basis}}
  ```

  `decision.actions` 会生成类似 `BUY SPY 100%，目标敞口 300%` 的文本；`decision.basis` 会列出命中
  条件和 `ema(8)=...`、`ema(13)=...` 等本次决策实际输入值。模板替换结果先生成纯文本，
  同时转换为自适应 HTML 版本，
  其中数值统一限制为最多三位小数。旧占位符继续兼容，但新模板应使用上述 `decision.*`
  名称。未知占位符或未闭合的双大括号会在保存任务时直接报错，不会原样发送到邮箱。

## 验证与运行

启动应用后，先在“实时决策”创建任务，确认策略历史数据覆盖、事件时间和邮件通道测试成功，再启动任务。建议先用收件人为自己的邮箱并观察一整个交易日。

测试命令：

```bash
python3 -m py_compile app.py database/realtime_repository.py services/realtime_*.py
python3 -m unittest discover -s tests -q
```

测试覆盖现有回测回归、三类代码面板公式、非代码三种模式、行情总览/候选池隔离、候选点、
非总览候选按需补数、缺日/未完成交易日检测、正式候选池失败关闭、数据请求去重和正式事件
优先通道、面板不请求外部 API、关闭自动更新后正式事件仍独立取数、无 15 秒轮询、七星种子
幂等、开盘使用上一交易日收盘、股票/加密事件数据边界和一分钟并发限频。出现“正式事件行情
不完整”时，系统不会用旧数据补算，会将事件标记为失败/跳过，需人工检查 Alpaca 连接、
交易时段及对应资产 feed。
