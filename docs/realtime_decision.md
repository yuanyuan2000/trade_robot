# 实时决策模块

本模块由两条用途严格隔离的链路组成：“行情总览标的实时观察面板”和“任务候选池正式
事件/邮件”。两者使用同一个策略定义，但观察面板是在最新数据库行情上模拟当前时点，
正式链路只在预定事件上执行；标的集合、输入快照、排名范围、目标含义与行情来源均可不同。
模块只提供交易辅助信息，不自动下单。

## 两条数据链路

| 项目 | 实时观察面板 | 正式决策与邮件 |
| --- | --- | --- |
| 标的集合 | `symbols.show_in_overview=1` 的全部标的 | 任务/run 策略快照中的候选池及必要辅助标的 |
| 当前价格 | 行情总览内部 SQLite 数据 | 事件时点独立请求 Alpaca IEX |
| 更新方式 | 面板可见时每 60 秒轮询内部 API | 只在 OPEN、CLOSE 或指定 `HH:MM` 事件执行 |
| 计算语义 | 按策略定义模拟以最新数据立即观察 | 按策略事件时钟进行正式决策 |
| 排名与目标 | 仅用于观察，并标记为“面板排名/面板目标” | 写入决策、邮件、组合状态和审计日志 |
| 外部 API | 禁止 | 允许且不受行情总览自动更新开关影响 |

面板不会把行情总览标的注入任务候选池，正式决策也不会使用面板排名。标的名前的蓝色小点
只表示它属于有效候选池；运行中读取 run 不可变快照，停止时读取任务快照。行情总览更新
与正式事件当前可以分别来自 SIP 和 IEX；系统保留来源信息，但本阶段不强制把两者统一。

## 阶段一：数据与一致性

- 实时任务创建时复制历史回测策略的完整快照；任务可选择持续跟随策略 revision。
- 任务启动时再次同步跟随策略；运行中的 run 使用不可变快照，停止后下一次启动才应用更新。
- 决策沿用 `BacktestEngine`、代码策略和 corporate actions 处理。代码策略通过可选的
  `observation_columns()`、`observe_latest()` 和 `observation_target_count()` 明确拥有自己的
  最新行情观察接口；没有实现该接口的策略在面板中显示不可计算。面板服务只构造数据库上下文、
  调用策略并渲染结果，不硬编码某个策略的中间指标。非代码策略仍使用同一 DSL 表达式。
- 每个事件保存行情来源、IEX feed、信号时间、填充参考价、数据清单、策略日志和组合状态。

## 行情更新与调度

- Alpaca 免费数据源固定使用 `feed=iex`；分钟事件取上一根完整分钟收盘作为信号价，当前分钟开盘仅作为人工执行参考。
- `OPEN` 使用上一交易日完整日线收盘，绝不使用当前日未完成日线；`CLOSE` 使用当日收盘且不伪造成交价。
- 交易日历按美东时区处理，支持开盘、收盘和 `HH:MM` 事件；超过 60 秒无法取得数据时跳过并记录原因。
- `IEXMarketDataHub` 不再运行 15 秒最新价轮询。每个正式事件现场获取可审计快照，事件以外
  不请求 IEX。
- `MarketOverviewRefreshCoordinator` 是唯一的行情总览后台更新所有者：启动时更新一次，
  自动开关开启后每 5 分钟更新一次。开关保存在 `system_settings`，行情页和实时决策页显示
  并修改同一个值；任一页面切换后会通过页面内状态事件立即同步另一个开关。关闭它不会
  禁止正式事件取数。

所有运行任务由一个可唤醒的中央调度线程维护。普通等待只计算并保存最近事件时间，不占用
`REALTIME_MAX_WORKERS` 事件线程，也不获取标的行情；最多每 30 秒进行一次状态兜底检查。
只有关键事件到点时才向线程池提交一次行情获取与决策计算，因此线程上限约束的是“同时发生
的关键事件”，而不是可运行任务总数。

普通等待状态点击终止会立即清除下次触发并结束运行记录。若关键事件已经开始获取行情、执行
策略或提交邮件，任务转为“终止中”，允许本次事件完整落库并提交通知，完成后自动停止；从
点击终止起不再调度后续事件。尚在线程池排队、但还未开始处理的事件可以直接取消。

## 实时数据面板

进入任务详情后默认显示面板，右上角图标分别切换面板、策略参数、通知设置、决策与邮件
日志。页面同一时刻只展示一块内容。

任务总览在桌面端采用四列紧凑卡片。竞争策略卡片复用下述面板计算结果，显示行情总览范围
内评分最高的三个合格标的，并按金、银、铜区分；不足三个时按实际数量显示，非竞争策略
不显示推荐。该推荐只用于总览观察，不改变正式任务候选池或邮件目标。

所有面板固定包含标的、最新价格、更新时间、策略状态/原因、面板排名与面板目标，并支持
搜索、候选池筛选、状态筛选、任意列升降序、固定表头和行级计算明细。动态指标列如下：

面板含义是：按任务当前有效策略快照，把内部数据库最新行情当成“现在”，模拟策略此刻会
计算出的中间量、过滤和排名。它不是最近一次正式决策，也不会展示最近正式决策值；策略
可以使用完整历史日线、当前价格或自建的暂定观测，所以“策略 WTME/ATR”等列与行情页采用
标准 K 线定义的指标不必相等。页面以小字和帮助提示持续说明这一差异。

面板顶部不再占用独立统计卡片；计算时间以及总览、候选池、通过、已过滤和不可计算数量
合并为工具栏下方的一行辅助信息，以便首屏容纳更多数据行。

- 七星：策略长期年化趋势、策略 R²、策略短期年化动量、策略量比（启用时）和策略最终评分；
- 急跌/ATR：N 日价格位移、策略 ATR 和策略 ATR 评分；
- 急跌/WTME：策略加权收益 `Rw`、策略加权标准化真实波幅 `Aw` 和策略 WTME 评分；
- 非代码：由任务自己的受限面板脚本定义。

每个指标列的悬停说明按任务当前生效参数展示回看天数、计算口径、用途和关键过滤阈值。非关键的逐日急跌明细、代入公式和输入值放在行级“查看”中，
避免表格过宽。数据不足或单标的公式失败只影响该行，状态显示“不可计算”。

“重新计算”及 60 秒自动轮询都调用 `GET /api/realtime/tasks/<id>/dashboard`，只读取主库；
响应明确返回 `source=market_overview_database` 和 `external_api_called=false`。结果有短时内存
缓存，价格更新时间、任务 revision、面板 revision 或策略 revision 变化时自动失效；另有
`observation_mode=strategy_latest_simulation`、`formal_decision=false` 供客户端与审计明确区分。

## 非代码面板脚本

创建非代码实时任务时自动生成可编辑的受限 JSON。它不是 Python/JavaScript，不支持导入、
网络、文件或任意代码执行，只允许现有 DSL 的 `price`、`position`、OHLCV、MA、EMA、ATR、
算术、比较和布尔运算。最多 12 个动态列。例如：

```json
{
  "version": 1,
  "columns": [
    {
      "key": "score",
      "label": "评分",
      "expression": "(price - close(5)) / atr(5)",
      "format": "number",
      "help": "用于当前面板标的之间排序的策略评分。",
      "event": "OPEN"
    }
  ],
  "default_sort": {"key": "score", "direction": "desc"}
}
```

脚本根据策略规则和 competition 配置自动提取指标，兼容 single、distribution、competition、
单标的、无过滤及无评分场景。它使用独立的 `panel_revision`，因此运行中也可校验和保存；
修改只影响展示列，不修改策略快照、正式规则、邮件和组合状态。“恢复自动生成”会明确覆盖
自定义脚本。

## 任务与 API

- 总览页“实时决策”卡片支持创建、启动、终止、删除和进入详情。
- 跟随策略或运行中时正式策略定义锁定；独立面板脚本仍可编辑。
- API 除任务 CRUD、`/start`、`/stop`、`/events` 外，还包括 `/dashboard`、`/panel`、
  `/panel/validate`、`/panel/regenerate` 和支持 `all/decision/mail` 筛选的 `/logs`。
- 删除是软删除；被实时任务引用的历史策略不能删除，避免破坏审计。

首次启动会幂等创建一个“七星ETF轮动实时决策（小池）”：默认停止、邮件关闭、跟随源
策略。七星小池与大池预置已确认使用同一 `SevenStarEtfRotationStrategy`、代码版本和默认
参数，只是候选池与描述不同。种子状态记录在 `realtime_task_seed_state`；软删除后不会复活。

## 阶段四：邮件与审计

- QQ SMTP 默认 `smtp.qq.com:465` SSL；Gmail SMTP 默认 `smtp.gmail.com:465` SSL，也支持 STARTTLS 配置。
- 邮件通道是发件身份（服务器、账号和授权码），收件邮箱是通知目标；两者填写同一个地址是合法的“自发自收”，不会重复发送。
- `.env` 中的 `QQ_ADDRESS`、`QQ_AUTHORIZATION_CODE` 仅在启动时加密写入本地通道，接口永不返回明文或密文。
- 密钥由 `REALTIME_MASTER_KEY` 或 `data/.realtime-master.key` 保护，文件权限为 600；生产环境应设置稳定的 `REALTIME_MASTER_KEY`。
- 普通事件发送由数据库原子限频，单任务至少间隔 60 秒；网络/临时失败最多按 10/30/120 秒重试，重试不占用新的普通发送额度。
- 通知、每次尝试、SMTP 错误、发送时间和完整正文均写入日志。代码策略邮件只保留前 12 条评分摘要，详细公式仍在事件 calculation 日志中。
- 急跌/ATR 与急跌/WTME 策略都按事件区分内容：风险检查邮件列出过滤结果与持仓处置，
  轮动选标邮件分别列出 ATR 动量或 WTME 评分、排名和调仓建议。
- 非代码策略模板是简单的纯文本替换，不是表达式语言。双大括号内只能使用系统定义的完整
  名称，不能填写自定义字符串、数字或公式；固定内容直接写在占位符外。可用占位符为：

  | 占位符 | 替换内容 |
  | --- | --- |
  | `{{task.name}}` | 任务名称 |
  | `{{decision.date}}` | 决策日期，如 `2026-08-05` |
  | `{{decision.time}}` | 规则时点原值，如 `OPEN`、`09:45` |
  | `{{decision.time_label}}` | 带美东时间说明的决策时点 |
  | `{{decision.datetime}}` | 决策日期与规则时点 |
  | `{{message.generated_at}}` | 邮件正文生成时间；不是 SMTP 实际送达时间 |
  | `{{decision.actions}}` | 一行或多行动作、标的与目标仓位 |
  | `{{decision.basis}}` | 命中规则、条件公式和本次指标实际值 |
  | `{{decision.summary}}` | 完整默认正文 |

  例如 SPY 8/13 EMA 策略可填写：

  ```text
  决策时点：{{decision.time_label}}
  邮件生成：{{message.generated_at}}
  决策内容：
  {{decision.actions}}
  决策依据：
  {{decision.basis}}
  ```

  `decision.actions` 会生成类似 `BUY SPY 100%` 的文本；`decision.basis` 会列出命中
  条件和 `ema(8)=...`、`ema(13)=...` 等本次决策实际输入值。所有替换结果都是文本，
  其中数值统一限制为最多三位小数。旧占位符继续兼容，但新模板应使用上述 `decision.*`
  名称。未知占位符或未闭合的双大括号会在保存任务时直接报错，不会原样发送到邮箱。

## 验证与运行

启动应用后，先在“实时决策”创建任务，确认策略历史数据覆盖、事件时间和邮件通道测试成功，再启动任务。建议先用收件人为自己的邮箱并观察一整个交易日。

测试命令：

```bash
python3 -m py_compile app.py database/realtime_repository.py services/realtime_*.py
python3 -m unittest discover -s tests -q
```

测试覆盖现有回测回归、三类代码面板公式、非代码三种模式、行情总览/候选池隔离、候选点、
面板不请求外部 API、关闭自动更新后正式事件仍请求 IEX、无 15 秒轮询、七星种子幂等、
开盘使用上一交易日收盘、IEX 事件数据边界和一分钟并发限频。出现 `IEX 行情不完整` 时
系统不会用旧数据补算，会将事件标记为失败/跳过，需人工检查 Alpaca 连接和交易时段。
