# 急跌回避与 ATR 动量轮动策略：当前实现、公式与改进建议

## 2. 一句话概括

该策略是“两阶段、横截面轮动”模型：

1. 在较早的盘中时点检查每个候选最近若干段是否发生百分比急跌或 ATR 标准化急跌，命中
   的标的当天进入 `risk_off`，若已经持有则立即卖出；
2. 在稍后的盘中时点，对所有候选计算“过去 N 日价格位移 / 前一交易日可知 ATR”，排除
   当天 `risk_off` 标的后按分数降序选前 K 只，以固定总目标仓位等权持有。

它试图把两个直觉组合起来：不去接正在快速下跌的“飞刀”，同时在剩余候选中持有相对
波动调整后上涨最强的标的。

## 3. 必须区分的三层配置

## 4. 每日事件顺序和数据可见性

设交易日为 `t`，风险检查时点为 `T_risk`，轮动时点为 `T_select`。

### 4.1 分钟事件的信号与成交分离

对于任意具体 `HH:MM` 事件：

| 内容 | 当前实现 |
| --- | --- |
| 信号价 | 目标时刻之前最近一根完整分钟 K 线的收盘价 |
| 成交参考价 | 目标时刻起第一根可成交分钟 K 线的开盘价 |
| 正常连续交易示例 | 09:40 信号读取 09:39 close，按 09:40 open 成交 |
| 停牌/熔断 | 信号退到目标前最近完整分钟；成交顺延到恢复后的第一根分钟 open |

因此策略不会读取 09:40 分钟尚未完成的 high、low 或 close 来决定 09:40 的订单，也不会
用恢复交易后的未来价格回头改变信号。

### 4.2 当天顺序

1. 开盘前应用拆股、确认分红应收，并用开盘价检查杠杆账户风险；
2. 到 `T_risk` 前，先扫描持仓的分钟级爆仓风险；
3. 在 `T_risk` 用事件信号价执行急跌检查，命中的已持仓标的生成 `SELL TARGET 0%`；
4. 卖单按 `T_risk` 的成交参考价模拟成交；
5. 到 `T_select` 前继续扫描爆仓风险；
6. 在 `T_select` 计算全部当日有效候选的 ATR 动量分数，排除 `risk_off`，确定目标；
7. 引擎统一先卖出非目标，再买入新目标；
8. 收盘保存现金、持仓、权益、收益、回撤和审计日志。

实时决策复用同一策略计算和状态，但只生成辅助建议，不向券商自动下单。实时任务通过
IEX 行情取得事件快照，并在两个事件之间持久化 `risk_off` 和模拟组合状态。

### 4.3 提前收市日

该策略没有像七星策略那样声明“映射到收市前若干分钟”的规则。只要用户配置的具体时刻
超出某个提前收市日的实际交易时段，数据预检就会 fail-closed 并停止回测。出厂默认的
09:40/10:00 不受常见 13:00 ET 提前收市影响，但配置下午时点时必须注意。

## 5. 数据口径与防止未来数据

### 5.1 日线与分钟线

- 风险检查历史段只使用当前交易日以前的完整日线；
- 每个观察窗口的最后一段使用“风险事件信号价 / 上一交易日收盘”；
- 动量分子使用轮动事件信号价和 N 个交易日前收盘；
- 动量分母是截至上一完整交易日可知的 ATR，不使用当天尚未完成的 high/low；
- 回测启动前把所需日线、事件分钟、交易日历和公司行动装入固定快照并保存哈希。

### 5.2 价格复权与成交价格

历史指标行通过 `daily_before()` 按当前决策日可知的拆股和现金分红进行点时复权，避免
拆股或除息制造虚假急跌/动量。成交、持仓盯市和账户现金仍使用原始价格；现金分红通过
应收和到账单独计入，避免重复计算收益。

这意味着公式中的历史 close、high、low 和 ATR 在同一决策日使用一致价格尺度，事件
分钟价和当天原始价格也与当日复权后的历史口径衔接。

### 5.3 晚成立候选与预热

候选只有在自身日线连续、完整并拥有足够预热历史后才加入当天 `context.universe`。代码
计算的最小预热长度为：

```text
drop_requirement = 1

若启用百分比急跌：
    drop_requirement = drop_lookback_sessions + 1

若启用 ATR 急跌：
    drop_requirement = max(
        drop_requirement,
        drop_lookback_sessions + atr_period + 1
    )

minimum_lookback = max(
    drop_requirement,
    momentum_lookback_sessions,
    atr_period + 1
)
```

晚成立标的在达到自身预热长度前不参与排名，也不能被交易。它有数据之后的日线缺口、
无效 OHLCV、不完整日线或事件分钟缺失仍会停止回测，不会自动填价。

## 6. 完整参数表

以下范围来自后端 schema；绕过前端也不能保存越界、非有限或类型错误的值。

| 参数键 | 界面名称 | 默认 | 合法范围 | 实际作用 |
| --- | --- | ---: | ---: | --- |
| `holdings_num` | 目标持仓数量 | 1 | 1–100，且不得超过候选数 | 排名取前 K 只；每个目标的策略仓位为 `target_weight / K` |
| `enable_percent_drop_filter` | 启用百分比急跌过滤 | 开 | 布尔值 | 控制是否用逐段百分比跌幅做硬过滤 |
| `drop_threshold_percent` | 单日急跌百分比阈值 | 5% | 0.1%–50% | 任一观察段跌幅小于等于负阈值即命中 |
| `enable_atr_drop_filter` | 启用 ATR 急跌过滤 | 关 | 布尔值 | 控制是否用逐段 ATR 标准化跌幅做硬过滤 |
| `drop_threshold_atr` | 单日急跌 ATR 倍数 | 2 | 0.1–20 ATR | 任一观察段变化小于等于 `-倍数` 即命中 |
| `drop_lookback_sessions` | 急跌观察交易日 | 3 | 1–20 | 决定风险检查覆盖的连续变化段数 |
| `risk_check_time` | 风险检查时间 | 09:40 | 09:30–15:59 ET 的具体 `HH:MM` | 读取此前完整分钟做硬过滤；必须早于轮动时间 |
| `selection_time` | 轮动选标时间 | 10:00 | 09:30–15:59 ET 的具体 `HH:MM` | 读取此前完整分钟计算排名和换仓 |
| `momentum_lookback_sessions` | 涨幅观察交易日 | 5 | 2–100 | 动量分子相对 N 个交易日前收盘计算 |
| `atr_period` | ATR 周期 | 5 | 2–100 | ATR 平滑周期；同时供评分和 ATR 急跌过滤使用 |
| `atr_weighting` | ATR 加权方式 | `wilder` | `wilder` / `ema` / `linear` / `simple` | 决定 TR 的时间权重 |
| `target_weight` | 入选标的总目标仓位 | 100% | 1%–100% | K 个完整目标合计的策略仓位，不含杠杆放大 |

### 6.1 参数间的交叉校验

- `risk_check_time < selection_time`，相等也不允许；
- `holdings_num <= 候选池数量`；
- 每个候选的 `max_weight` 必须至少为 `target_weight / holdings_num`；
- 时间参数必须是具体 `HH:MM`，不能填 `OPEN` 或 `CLOSE`；
- 数值必须有限，布尔值不能冒充 0/1 数字；
- 未知参数会被拒绝；
- 两种急跌过滤可以同时开启，也可以同时关闭。两者都关闭时风险事件仍执行并写日志，
  但不会产生 `risk_off`。

### 6.2 候选行参数

每个 `definition.symbols[]` 还包含：

| 字段 | 默认 | 合法范围 | 含义 |
| --- | ---: | ---: | --- |
| `symbol` | 无 | 至少 1 个；不能为空或重复 | 候选代码，经统一代码格式规范化 |
| `max_weight` | 100% | `0 < max_weight <= 100%` | 策略语义下该标的最大仓位上限；还必须不低于 `target_weight / holdings_num` |
| `leverage_multiplier` | 1× | 1–10× | 单标的杠杆；与账户整体杠杆相乘 |

假设策略目标仓位为 50%，账户整体杠杆为 2×，该标的杠杆为 3×，实际目标敞口为：

```text
actual_exposure = 50% × 2 × 3 = 300% of account equity
```

手续费和滑点按实际放大后的成交数量计算。策略目标、`max_weight` 和等权分配仍保持
0%–100% 的未放大语义。

## 7. ATR 计算公式

设第 i 个完整日线为 `(H_i, L_i, C_i)`，前一日收盘为 `C_(i-1)`。

### 7.1 真实波幅 TR

```text
TR_i = max(
    H_i - L_i,
    abs(H_i - C_(i-1)),
    abs(L_i - C_(i-1))
)
```

TR 同时覆盖日内振幅和隔夜跳空。

### 7.2 Simple ATR

最近 N 个 TR 等权：

```text
ATR_i = (TR_(i-N+1) + ... + TR_i) / N
```

窗口外数据完全退出，解释简单，但窗口边界可能产生跳变。

### 7.3 Linear ATR

最近 N 个 TR 从旧到新使用权重 `1..N`：

```text
denominator = N(N+1)/2
ATR_i = Σ(j * TR_(i-N+j)) / denominator,  j=1..N
```

它是固定窗口，近期响应比简单平均快，权重结构直观。

### 7.4 Wilder ATR

先用最早 N 个 TR 的简单平均初始化，之后：

```text
alpha = 1/N
ATR_i = alpha * TR_i + (1-alpha) * ATR_(i-1)
      = (TR_i + (N-1) * ATR_(i-1)) / N
```

这是出厂默认值，最平滑，并用于兼容已有回测结果。

### 7.5 EMA ATR

初始化方式与 Wilder 相同，之后：

```text
alpha = 2/(N+1)
ATR_i = alpha * TR_i + (1-alpha) * ATR_(i-1)
```

EMA 对近期波动响应更快。当前参数提示推荐轮动策略研究 EMA，但切换会改变评分和 ATR
急跌过滤两处结果，不能与 Wilder 回测直接混作同一策略版本比较。

## 8. 阶段一：急跌风险检查

设 `L = drop_lookback_sessions`。风险事件前，系统取得当前交易日以前最后 L 个完整日线：

```text
R_0, R_1, ..., R_(L-1)
```

并构造 L 个连续变化段：

```text
Close(R_0)     -> Close(R_1)
Close(R_1)     -> Close(R_2)
...
Close(R_(L-2)) -> Close(R_(L-1))
Close(R_(L-1)) -> P_risk
```

其中 `P_risk` 是风险时点以前最后一根完整分钟的收盘价。因此参数 L 表示检查 L 个变化段，
最后一段是“昨日收盘到今天风险事件”的盘中变化。

### 8.1 百分比急跌

每段从价格 `P_prev` 到 `P_current`：

```text
change_percent = P_current / P_prev - 1
```

若开启过滤并满足：

```text
任一 change_percent <= -drop_threshold_percent / 100
```

则记录过滤代码 `percent_drop`。边界是闭区间，例如阈值 5% 时恰好 -5% 也触发。

### 8.2 ATR 标准化急跌

对同一变化段，分母使用变化开始时 `P_prev` 所在完整日线结束时已经可知的 ATR：

```text
change_atr = (P_current - P_prev) / ATR_at_previous_bar
```

若开启过滤并满足：

```text
任一 change_atr <= -drop_threshold_atr
```

则记录过滤代码 `atr_drop`。这种对齐方式不会用变化结束日的 high/low 为该段下跌提前提供
信息；最后一段使用上一交易日结束时的 ATR。

### 8.3 两种过滤的组合

两种过滤是 OR 关系：任意一个启用规则命中，标的就进入当天 `risk_off`。代码同时保存
所有命中原因，不会因为先命中百分比规则就跳过 ATR 诊断。

若标的已持有，风险事件生成：

```text
SELL symbol, sizing_mode=TARGET, value_percent=0
```

若未持有，只记录过滤状态，不产生空卖订单。`risk_off` 仅对当天有效，下一交易日重新检查。

## 9. 阶段二：ATR 动量评分与排名

设：

- `M = momentum_lookback_sessions`；
- `N = atr_period`；
- `P_select` 为轮动时点以前最后完整分钟收盘；
- `C_base` 为 `daily_before()` 中倒数第 M 根日线的复权收盘；
- `ATR_prev(N)` 为截至上一完整交易日的 N 周期 ATR。

当前评分公式为：

```text
score = (P_select - C_base) / ATR_prev(N)
```

### 9.1 分数含义

- 分子是 M 个交易日左右的绝对价格位移；
- 分母是“一天典型真实波幅”的绝对价格单位；
- 分数可以理解为这段价格位移相当于多少个近期日 ATR；
- 价格和 ATR 同比例缩放，因此拆股等纯价格尺度变化不会改变分数；
- 它不是收益率、Sharpe、年化收益或统计显著性，M 变化后分数也没有做时间尺度归一化。

### 9.2 排名与硬过滤

所有当日已具备数据资格的候选都会计算并记录分数，包括已经 `risk_off` 的标的；但只有
未被硬过滤且 ATR 大于 0 的候选进入可选列表。

```text
ranked = sort(eligible_scores, key=(-score, symbol))
targets = ranked[:holdings_num]
```

分数高者优先；完全同分时按标的代码字母顺序决定，不按候选池原始顺序。

当前没有“分数必须大于 0”的条件。如果所有合格候选分数均为负，策略仍会选择其中最高、
也就是跌幅相对最小的一组。若 ATR 等于 0，该标的分数记为不可计算且不进入排名。

## 10. 目标仓位与换仓

设：

```text
K = holdings_num
W = target_weight
per_symbol_target = W / K
```

### 10.1 合格候选不足

分母始终是配置的 K，而不是当天实际入选数量。例如 `K=3, W=90%`，但只有 1 只合格：

```text
该标的目标 = 30%
剩余 60% 目标槽位留现金
账户其余 10% 也为现金
```

策略不会把空缺份额重新分给剩余候选。

### 10.2 卖出

轮动事件会把“当前持有但不在 target_set”的候选卖到 0%。同一事件中引擎始终先卖后买，
卖出资金可以用于随后买入。

### 10.3 买入和 v1.3.0 的持有语义

只有目标标的当前数量为 0 时才生成买单。已经持有且继续入选的标的不生成订单，因此：

- 不会每天把同一赢家重新调回精确目标权重；
- 不会因账户杠杆或价格漂移反复成交；
- 多持仓时，继续入选的旧目标可能偏离等权，新进入目标按当时权益买到目标比例；
- 当前没有“偏离超过 X% 才再平衡”的可配置容差。

这是 v1.3.0 有意引入的“目标不变则持有”行为，不是漏执行。

### 10.4 TARGET 仓位与交易成本

新目标的实际下单数量由组合层根据当前权益、当前持仓价值、有效杠杆、成交参考价、滑点、
手续费和数量步长求解。主要口径：

```text
commission = max(quantity * commission_per_share, minimum_commission)
buy_fill   = reference_price * (1 + slippage_bps / 10000)
sell_fill  = reference_price * (1 - slippage_bps / 10000)
```

默认只买整数股；开启碎股后通常精确到 `0.000001` 股，资产可声明更严格的步长。代码策略
只允许多头现货，不会生成空头。

## 11. 完整数值示例

假设：

- 百分比阈值 5%；
- ATR 急跌阈值 2；
- 上一日收盘 101；
- 风险事件信号价 94；
- 上一日可知 ATR 为 2.5。

最后一段百分比变化：

```text
94 / 101 - 1 = -6.931%
```

因为 `-6.931% <= -5%`，命中 `percent_drop`。

ATR 标准化变化：

```text
(94 - 101) / 2.5 = -2.8 ATR
```

若 ATR 过滤开启，因为 `-2.8 <= -2`，也命中 `atr_drop`。即使后续轮动时价格反弹，该标的
当天仍保持 `risk_off`，不会重新买回。

另一个未过滤候选在轮动时：

```text
M 日前收盘 = 90
轮动事件价 = 105
上一日 ATR = 3
score = (105 - 90) / 3 = 5
```

其含义是这段价格位移约为 5 个近期日 ATR。系统对所有未过滤候选按该分数排名。

## 12. 日志、邮件与 XLS 审计

### 12.1 风险日志

每个候选在风险事件写入 `RAPID_DROP_ATR_RISK_CHECK`，结构化上下文包括：

- 每段起止日期、前值、后值、百分比变化和代入公式；
- 若启用 ATR 过滤，每段 ATR、ATR 标准化变化和代入公式；
- 风险事件价、两种阈值；
- `filter_codes` 与中文 `filter_reasons`。

### 12.2 排名日志

每个候选在轮动事件写入 `RAPID_DROP_ATR_DAILY_SCORE`，包括：

- 当前价、基准价、基准日期；
- ATR、周期、加权方式；
- 代入具体数值的评分公式和原始 score；
- 合格排名、是否最终入选；
- 风险阶段的全部过滤代码、变化序列和风险事件价。

### 12.3 导出与实时邮件

回测 XLS 的“策略自定义日志”按日展开：每个候选各有评分公式/结果列，并汇总百分比急跌、
ATR 急跌、最终操作、操作点位、标的和卖出 PnL。

实时邮件在风险事件列出过滤结果和持仓处置，在轮动事件列出 ATR 动量评分、排名和调仓
建议。邮件只是人工辅助，不代表券商订单已提交或成交。

## 13. 设计原理与优点

### 13.1 硬过滤和软排名分离

急跌是“是否允许参与”的离散风险条件，ATR 动量是“允许参与者中谁更强”的连续分数。
两者分离使过滤原因和排名原因可独立审计，也避免一个极端高动量分数覆盖明确风险事件。

### 13.2 ATR 标准化提升跨标的可比性

直接比较美元涨幅会偏向高价标的，比较简单收益率又不反映波动差异。用绝对位移除以 ATR
同时消除价格单位，并对高波动标的施加自然惩罚，适合横截面排名。

### 13.3 双急跌口径互补

- 百分比阈值容易解释，适合控制账户能容忍的绝对单日跌幅；
- ATR 阈值随标的自身波动变化，能区分“正常波动”和“相对异常下跌”；
- 两者独立开关允许做单因素或组合研究。

### 13.4 两个盘中时点

风险检查早于轮动，允许先处理突发风险，再用稍后的信息选择目标；相比开盘瞬间决策，能
避开部分开盘噪声。与此同时，使用事件前完整分钟和事件后 open 保持了可执行、无前视的
回测边界。

## 14. 当前实现的重要限制

1. **风险检查只执行一次。** `T_risk` 之后、`T_select` 之前的新急跌不会重新进入硬过滤，
   只能通过较低动量分数间接影响排名。
2. **观察的是离散收盘/事件价，不是段内最低价。** 标的盘中暴跌后在风险检查前完全恢复，
   当前公式可能看不到这次极端路径。
3. **没有正动量门槛。** 全部候选为负时仍持有“最不差”者，不能自动转现金或防御资产。
4. **动量只比较两个端点。** 中间路径、趋势稳定性、回撤和反转结构都不进入分数。
5. **同一 ATR 配置承担两个目标。** 风险异常检测可能需要快速 ATR，动量归一化可能需要
   稳定 ATR；当前周期和加权方式被绑定。
6. **目标不变时完全不再平衡。** 能减少换手，但多目标权重可能长期漂移，也没有上/下限
   容差。
7. **没有排名缓冲。** 第一、第二名小幅互换也可能触发完整换仓，容易受噪声和成本影响。
8. **只做等权，不看相关性。** 多只目标可能高度同质，等权不等于风险等权。
9. **固定阈值不适应波动制度。** 5% 在低波动期很极端，在危机期可能频繁触发。
10. **没有防御标的。** 合格数不足时只留现金；现金收益和替代资产机会没有建模为信号。
11. **候选池由用户静态维护。** 结果受幸存者偏差、行业集中、单股事件和池选择显著影响。
12. **成交模型仍是分钟级近似。** 大单冲击、盘口深度、开盘价可成交量和 IEX/SIP 差异未
    被完整模拟。
13. **下午参数可能与提前收市冲突。** 该策略没有自动映射，预检会直接失败。

## 15. 未来改进建议

以下均为建议，当前版本尚未实现。任何改变公式、候选资格或交易语义的改动都应提升
`code_version` 并保存迁移说明，避免新旧回测混淆。

### 15.1 第一优先级：降低明显的实盘风险

1. **在轮动时再次执行急跌检查。** 复用同一公式检查 `T_risk -> T_select` 的变化，或把
   风险事件状态更新到轮动前，堵住两事件之间的风险空窗。
2. **增加正动量/最低分门槛。** 例如 `score > 0` 或用户可配最小分数；无候选时持有现金
   或防御标的，避免熊市中被迫买入负动量标的。
3. **加入排名缓冲与最短持有期。** 例如旧目标只要仍在前 `K+B` 就继续持有，降低相邻名次
   抖动造成的换手。
4. **增加可选再平衡容差。** 只有目标权重偏离超过阈值才调整；保留 v1.3.0 的低换手优点，
   同时限制多持仓漂移。
5. **组合级风险上限。** 增加最大实际敞口、单行业上限、最大回撤降仓和杠杆约束，特别是
   当前数据库使用 2×/3× 单标的杠杆时。

### 15.2 第二优先级：改进信号质量

1. **拆分两套 ATR 参数。** `risk_atr_period/weighting` 与
   `momentum_atr_period/weighting` 独立，分别服务异常检测和排名稳定性。
2. **增加路径质量。** 在端点位移之外加入线性回归斜率、R²、最大回撤或正收益日比例，
   区分平稳趋势与单日跳涨。
3. **加入盘中极值风险。** 使用事件前完整分钟序列的最低价/最大回撤检测“暴跌后修复”，
   但必须严格限定在事件以前，避免前视。
4. **波动目标或风险预算。** 用逆波动分配替代纯等权，并加入相关性/聚类约束，避免多个
   高相关目标叠加风险。
5. **自适应阈值。** 用历史分位数或市场波动制度调整百分比/ATR 阈值，同时保留上下限和
   稳定期，防止参数每日跳变。
6. **市场状态过滤。** 可使用宽基长期趋势、波动指数或市场广度决定总目标仓位，但要避免
   将同一候选数据重复用于过多筛选造成过拟合。

### 15.3 第三优先级：研究与验证体系

1. **Walk-forward 和样本外验证。** 参数只在训练窗选择，在后续未见窗口评估；滚动重复，
   不以单次全样本最优为结论。
2. **参数稳定性图。** 对 L、M、ATR 周期、阈值、持仓数和时点做网格/随机搜索，优先选择
   邻域稳定而非孤立峰值。
3. **交易成本压力测试。** 同时提高滑点、最低手续费和成交延迟，检查收益是否依赖理想
   分钟开盘成交。
4. **候选池偏差审计。** 使用历史时点可得的成分池，记录新增/移除日期，避免用今天的赢家
   列表回测过去。
5. **Bootstrap/置换检验。** 评估横截面排名是否显著优于随机持有、等权基准和简单动量，
   并控制多参数尝试带来的数据窥探。
6. **IEX 与 SIP 偏差对照。** 对实时事件价、延迟和缺失率做并行审计，确认免费 feed 不会
   系统性改变风险过滤或排名。
7. **不可变研究配置。** 为每组研究参数生成配置 ID、代码版本、数据哈希和结果快照，避免
   当前可编辑策略与历史结论脱节。

## 16. 建议的改进顺序

如果目标是先提高现有策略的稳健性，而不是立即重做模型，建议顺序为：

1. 轮动时二次风险检查；
2. 最低分/正动量门槛与现金或防御资产；
3. 排名缓冲和再平衡容差；
4. 组合实际敞口与行业集中上限；
5. 拆分风险 ATR 与动量 ATR；
6. 完成 walk-forward、成本压力和候选池偏差审计后，再考虑更复杂的趋势/制度模型。

该顺序优先修复“风险空窗、负动量仍满仓、噪声换手和杠杆集中”等可解释问题，然后才
增加模型复杂度，有利于保持审计性并降低过拟合风险。
