## 1. 结论摘要

当前评分公式存在应修复的算法错误，而不只是“非标准但可接受”的写法：

1. `np.polyfit(..., w=w)` 实际最小化 `Σ(w·residual)²`，等价于残差重要性
   `w²`；当前 R² 的残差平方和与总平方和却使用 `w`，口径不一致。
2. 当前总平方和使用普通均值，而不是与平方和权重一致的加权均值。
3. 上述不一致会产生负 R²；负长期收益再乘负 R² 会得到正分，并真实触发交易。
4. `ss_tot != 0` 的精确判断还有近零方差数值问题，完全恒价也可能得到负 R² 和微小
   正分。
5. `exp(250 * slope) - 1` 作为收益展示有数学含义，但作为 25 日趋势的排名因子会产生
   很强的指数凸性，不宜与正确性修复混在同一次上线中。

建议先发布兼容性修复：保留当前 `polyfit` 斜率，令 R² 的有效权重统一为 `w²`，总平方和
使用 `w²` 加权均值，并补充近零方差、R² 截断和正斜率保护。去指数化评分应作为下一版
策略模型单独走滚动样本外验证。

## 2. 当前实现的数学问题

当前实现位于 `services/backtest/code_strategies.py::_weighted_trend`：

```text
y = log(price)
w = linspace(1, 2)
slope, intercept = polyfit(x, y, 1, w=w)
annualized = exp(250 * slope) - 1
SSres = Σ w * residual²
SStot = Σ w * (y - mean(y))²
R² = 1 - SSres / SStot
score = annualized * R²
```

本机 NumPy 2.2.6 的 `polyfit` 文档明确说明，`w[i]` 施加在“未平方残差”上。因此拟合
目标是：

```text
min Σ [wᵢ(yᵢ - fittedᵢ)]² = min Σ wᵢ² residualᵢ²
```

当前最近点与最早点的回归残差惩罚比实际为 `4:1`，但 R² 使用 `2:1`。此外，若平方和
使用权重 `q`，中心也应为 `Σ(q·y)/Σq`。只改均值而不改残差权重会令分母下降，却不会
修复不一致，反而可能产生更多负 R²。

非退化情况下当前 R² 一定不大于 1，但没有非负保证。可复现样本：

```python
prices = [98, 100, 102, 102, 102, 98]
```

当前结果为：

```text
annualized = -0.4662931059
R²         = -0.0388854031
score      = +0.0181319954
```

默认评分开区间是 `0 < score < 100`，所以如果其他过滤没有命中，下降趋势会以正分进入
排名。

完全恒价也存在独立数值边界：

```python
prices = [50.03] * 26
```

当前返回 `annualized=-3.9968e-15`、`R²=-5.53846`、`score=+2.2136e-14`。
原因是浮点误差令总平方和成为极小非零值，而代码只使用精确的 `ss_tot != 0`。

| 完整标准线性 WLS + 对数趋势评分 | 362.01% | 26.61% | 23.62% | 0.868 | 589 | 73 | 0 | 0 |

解读：

- 只改均值的历史表现较好，却产生更多负 R² 和错误入选，不能部署。
- 只截断 R² 以很小的绩效代价消除了双负路径，但仍没有修复统计口径，适合作为紧急保护，
  不适合作为最终方案。
- 保留现有斜率、令 R² 完整使用有效权重 `w²` 的兼容修复消除了负 R²，历史收益和
  Sharpe 略高于基线，但最大回撤略高；它的部署依据是数学一致性，不是收益改善。
- 标准线性 WLS 单独使用时本样本表现下降；这不说明它数学错误，而是它把近期点的重要性
  从当前实际的 4:1 改为 2:1，属于模型语义变化。
- 标准线性 WLS 与对数评分的组合在全样本指标最好，但两个单项并未分别改善，年度结果也
  不一致。这是交互效应和样本期结果，不能当作样本外证据直接部署。

## 7. 指数年化审查

`exp(250*slope)-1` 假定短窗趋势可持续一年。25 日窗口相当于把拟合窗口外推约 10 倍：

- 窗口平滑上涨 10%，年化约 159%；
- 窗口平滑上涨 20%，年化约 519%；
- 窗口平滑上涨 30%，年化约 1,279%。

真实日志中长期拟合年化最大值为 316.659，即 31,665.9%；评分最大值 294.335。当前
`score < 100` 只过滤一部分极值：2026-03-12 的 USO 拟合年化仍达到 8,770.7%，R² 为
0.783，评分 68.709，并成为当日目标。

单独去掉指数变换后，全样本表现接近基线，但被选中标的的“诊断年化”最大值反而升至
31,592.4%，因为原本偶然承担异常过滤作用的 `score < 100` 在新量纲下几乎不再触发。
因此不能只换评分公式而沿用原阈值。

建议排名使用线性的对数趋势：

```text
score = 250 * slope * R²
```

其中乘 250 只改变显示量纲，不改变固定回看期下的排名；也可以使用
`lookback * slope * R²`。原指数年化值可保留用于展示，但需要把异常控制拆成独立、可解释
的条件，例如正斜率、最低 R²、最大窗口收益或最大日对数斜率。现有 `max_score=100` 和
放量年化阈值需要重新定义和校准。

## 8. 推荐上线顺序

### 8.1 应立即修复的正确性问题

兼容方案保留当前回归斜率：

```python
fit_weights = np.linspace(1.0, 2.0, len(y))
importance = fit_weights**2
slope, intercept = np.polyfit(x, y, 1, w=fit_weights)
weighted_mean = np.average(y, weights=importance)
ss_res = np.sum(importance * (y - fitted) ** 2)
ss_tot = np.sum(importance * (y - weighted_mean) ** 2)
```

还应同时：

1. 对恒价或近恒价序列使用尺度相关容差，直接返回零趋势、零 R²、零评分；
2. 将最终 R² 截断到 `[0,1]`，只吸收机器精度误差；
3. 资格判断显式要求 `slope > 0` 或 `annualized > 0`，形成第二道符号保护；
4. 使用 `expm1(250*slope)` 并检查有限值和溢出；
5. 把策略版本从 1.0.0 升级，避免相同版本静默产生不同历史结果；
6. 将现有“复刻原公式”的单元测试改为数学不变量测试，并保留旧公式作为迁移对照。

建议测试覆盖：恒价、近恒价、负趋势反弹、随机正价格下 `0<=R²<=1`、评分符号、价格尺度
不变性、非法输入和新旧信号差异快照。

### 8.2 应作为新模型验证、不要与修 bug 混发

1. 若产品定义确实希望最近点重要性只是最早点的 2 倍，改用
   `np.polyfit(..., w=sqrt(importance))`；
2. 将排名从指数年化收益改为线性对数趋势；
3. 增加独立的最低 R² 和过热/异常斜率条件；
4. 采用滚动训练/验证、不同起止日期、不同池和滑点敏感性测试，不能只选择本表全样本最高
   的组合。
