# 急跌回避与 WTME 的通达信实现

本次目标是把项目 `rapid_drop_wtme_rotation` 的过滤、评分和排名结果迁移到通达信，用于观察，不执行交易。

## 1. 当前公式配置

| 参数 | 通达信名 | 缺省值 |
| --- | --- | ---: |
| WTME 观测数 | `NN` | 13 |
| 半衰期 | `HH` | 6 |
| 分母稳定项 | `EPS` | `1e-8`，源码固定 |
| 急跌观察变化段 | `LB` | 5 |
| 单段急跌阈值 | `DP` | 5% |

这些缺省值匹配本次实际使用配置。项目策略类本身的初始默认值可能不同，迁移其他实例时应以该实例保存的参数为准。

原策略在 09:50 固定急跌过滤结果，10:00 再评分。通达信公式为了随时在手机查看，按最新价动态重算，并不保存原策略的日内快照。因此结果表示“现在按同一数学口径计算会怎样”，不等于历史上每一天 10:00 的严格回放。

## 2. 急跌过滤

对最近 `LB` 个相邻价格变化段计算：

```text
r_t = C_t / C_(t-1) - 1
```

任一段满足：

```text
r_t <= -DP / 100
```

当前标的即被过滤。通达信实现为：

```text
PC:=REF(C,1);
RET:=IF(PC>0,C/PC-1,0);
DROP0:=COUNT(RET<=-DP/100,LB)>0;
```

`LB / DP` 与 WTME 的 `NN / HH / EPS` 数学上相互独立。纯急跌条件选股不应额外要求 13 根 WTME 观测。

## 3. WTME 评分

每个观测定义：

```text
r_i  = (C_i - C_(i-1)) / C_(i-1)
TR_i = max(H_i-L_i, abs(H_i-C_(i-1)), abs(L_i-C_(i-1)))
a_i  = TR_i / C_(i-1)
q_i  = 2^(-(N-1-i)/h)
```

权重归一化后：

```text
Rw   = sum(w_i * r_i)
Aw   = sum(w_i * a_i)
WTME = 100 * Rw / (Aw + epsilon)
```

最新盘中日 K 尚未完成，原策略不能使用当天稍后才知道的最高价和最低价。因此当前观测按“昨收 → 当前价”构造：

```text
open  = 昨收
high  = max(昨收, 当前价)
low   = min(昨收, 当前价)
close = 当前价
TR    = abs(当前价 - 昨收)
```

公式中的关键处理是：

```text
POINTTR:=IF(ISLASTBAR,ABS(C-PC),FULLTR);
```

这与项目行情页中直接使用未完成日 K 当前 `H/L` 的“标准 WTME 指标”不同，不要混用两者的绝对分数。

## 4. 有限窗口权重

通达信没有循环。本实现用 `DMA` 的递推结果减去窗口尾部，精确得到最近 `NN` 个有限几何权重，而不是用无限 EMA 近似。

令：

```text
d = 2^(-1/h)
E_t = (1-d)X_t + dE_(t-1)
```

则：

```text
(E_t - d^N * E_(t-N)) / (1-d^N)
```

恰好等于最近 `N` 项按 `1,d,d^2,...` 加权后的归一化均值。`RW0` 和 `AW0` 都使用这一恒等式。

## 5. 文件作用

| 文件 | 平台 | 类型 | 作用 |
| --- | --- | --- | --- |
| `WTMES.txt` | PC | 技术指标 | 单标的完整 WTME、急跌状态、合格状态和排序值 |
| `WTMENOWRANK.txt` | PC | 技术指标 | 在本地“WTME池”显示当前动态名次 |
| `WTMETOPN.txt` | PC | 条件选股 | 用 `Ctrl+T` 从本地“WTME池”选当前前 `TOPN` 名 |
| `WTMEAPPXG.txt` | PC/APP | 条件选股 | 自包含的纯急跌过滤模板；入口候选宇宙包含目标证券时才有效 |
| `WTMEAPPSORT.txt` | PC/APP | 技术指标 | 只有一个 `SORTV` 输出的跨证券辅助指标 |
| `WTMEPOOLDASH.txt` | PC | 技术指标 | 用 `CALCSTOCKINDEX` 读取固定五标的并显示分数和最高者 |
| `WTMEPOOLDASHM.txt` | APP | 技术指标 | 用 `$` 读取固定五标的，在副图内降序显示合格名称与评分 |
| `validate_formula_parity.py` | 开发验证 | Python | 对照项目实现验证有限 DMA、盘中 WTME 和急跌结果 |

## 6. `WTMES` 输出接口

输出顺序不能随意修改：

| 序号 | 名称 | 含义 |
| ---: | --- | --- |
| 1 | `WTME` | 策略口径评分 |
| 2 | `RW` | 加权收益 |
| 3 | `AW` | 加权标准化真实波幅 |
| 4 | `RDROP` | 是否命中急跌 |
| 5 | `ELIG` | 历史足够且未急跌 |
| 6 | `SORTV` | 合格时为评分，否则为 `-999` |

`-999` 位于 WTME 正常范围外，用来确保过滤项排在所有真实评分之后。真实负分仍然是合法评分，不能误当成不合格。

## 7. PC 使用流程

1. 创建 `WTMES`，参数设为 `NN=13 / HH=6 / LB=5 / DP=5`，日线副图。
2. 创建自定义板块“WTME池”，加入候选标的。
3. 若想查看单标的当前名次，创建 `WTMENOWRANK`。
4. 若想筛选前 N 名，创建条件选股公式 `WTMETOPN`，设置 `TOPN`，通过 `Ctrl+T` 在“WTME池”运行。
5. 固定五标的看板可创建 `WTMEAPPSORT` 后再创建 `WTMEPOOLDASH`。

PC 固定池目前为：

```text
SH518880  黄金ETF
SZ161226  白银LOF
SH501018  南方原油LOF
SH513100  纳指ETF
SZ159915  创业板ETF
```

## 8. APP 使用流程

1. 在指标平台创建并上传 `WTMEAPPSORT`，参数缺省值设为 `13 / 6 / 5 / 5`。
2. 确认它在单个证券日 K 上能计算 `SORTV`。
3. 创建并上传 `WTMEPOOLDASHM`，不设置参数。
4. 在任意日 K 副图加载 `WTMEPOOLDASHM`。
5. 看板通过下列语法直接读取固定证券：

```text
SH518880$WTMEAPPSORT.SORTV
```

6. 看板在公式内部用两两比较生成唯一名次，只显示未被过滤的名称和评分；第一名黄色，完全同分时按证券代码升序。
7. 公式编辑器“显示小数”建议设为 `3`。

这一方案是为绕过 APP 指标选股入口对部分 LOF 的预先剔除。它不依赖 APP 把两只 LOF 放入条件选股候选宇宙。

## 9. 修改固定池

PC 修改 `WTMEPOOLDASH` 中五条 `CALCSTOCKINDEX`；APP 修改 `WTMEPOOLDASHM` 中五条 `$` 引用。与此同时还要同步：

- 变量名称与显示名称；
- 排名比较式；
- 同分优先顺序；
- 每一名对应的文字显示条件。

如果候选池经常变化或数量很多，手写比较会迅速膨胀，应回到 PC 的板块 `INSORT`，或在项目服务端计算后向手机展示。固定五标的是手写 APP 看板最合适的规模。

## 10. 验证与已知边界

运行代数对照：

```bash
python other_platform/TDX/validate_formula_parity.py
```

脚本验证的是公式代数与项目 Python 计算，不模拟通达信编译器。

已知边界：

- 动态公式不保存原策略 09:50/10:00 快照。
- 历史曲线最右端使用盘中点时口径，过去各点不是逐日 10:00 回放。
- 通达信数据源、复权和实时更新时间可能与项目不同。
- APP 不支持本次 PC 公式使用的 `CALCSTOCKINDEX / ISVALID`，因此保留独立手机版。
- APP 条件选股入口可能在公式执行前排除某些 LOF；固定池看板是最终可用方案。
